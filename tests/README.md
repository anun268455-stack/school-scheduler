# ตัวทดสอบ

```bash
./tests/run.sh
```

ไม่ต้องลงอะไรเพิ่ม ใช้ `python3` กับ `node` ที่มีอยู่แล้ว

## ทำไมอยู่ที่นี่

ตัวทดสอบเคยอยู่ในที่ทำงานชั่วคราวนอก repo แล้วหายไปพร้อมเครื่องทุกครั้งที่
เครื่องถูกเปลี่ยนใหม่ — เสียไปแล้วสองรอบ ของที่ต้องรอดไปกับโค้ดก็ต้องอยู่กับโค้ด

## ที่นี่มีอะไร

| โฟลเดอร์ | คืออะไร |
|---|---|
| `py/` | ตัวทดสอบฝั่งเซิร์ฟเวอร์ — เรียกฟังก์ชันของ `mock_api.py` ตรง ๆ ไม่ผ่าน HTTP |
| `ts/` | ตัวทดสอบตัวคิดฝั่งหน้าเว็บ — ไฟล์ใน `frontend/src/utils` ที่เป็นฟังก์ชันล้วน |
| `stubs/` | `fastapi` ของปลอม |

`stubs/` มีอยู่เพราะเครื่องที่ใช้พัฒนาลง `fastapi` ไม่ได้ (ไม่มีเน็ตออกไปที่
pypi) และเพราะเซิร์ฟเวอร์ใช้จาก `fastapi` แค่สามอย่าง — `FastAPI`,
`HTTPException`, และ middleware สองตัว — จึงปลอมได้ครบโดยไม่บิดความจริง
ของปลอมยังเก็บลำดับการเพิ่ม middleware ไว้ให้ตรวจได้ด้วย

ฝั่ง TypeScript ใช้ `node` รันไฟล์ `.ts` ได้เองตั้งแต่ node 22 จึงไม่ต้องมี
`node_modules` — แต่ตัวทดสอบจึงนำเข้าได้เฉพาะไฟล์ที่ไม่พึ่ง React หรือ axios
ซึ่งตรงกับเจตนาอยู่แล้ว: ตัวคิดควรแยกออกมาจากหน้าจอให้ทดสอบได้ตรง ๆ

## กติกา

ไฟล์ทดสอบต้องพิมพ์คำว่า `ALL PASS` เมื่อผ่าน และต้องไม่พิมพ์เมื่อไม่ผ่าน
(`run.sh` ตัดสินด้วยคำนี้) ไฟล์ไหนแตะ `SLOTS` หรือ `ELECTIVE_POOLS` ให้ล้าง
ของตัวเองเมื่อจบ เพราะทุกไฟล์ใช้โมดูลร่วมกัน

เขียนคำอธิบายเป็นภาษาไทยเหมือนโค้ดส่วนอื่น และเขียนให้บอกว่า **ทำไมข้อนั้นสำคัญ**
ไม่ใช่แค่ว่ามันเช็คอะไร — ข้อที่มีอยู่ส่วนใหญ่มาจากอาการที่โรงเรียนเจอจริง
