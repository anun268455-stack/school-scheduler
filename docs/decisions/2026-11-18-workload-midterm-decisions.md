## 1. คำตัดสินทุกข้อ (ตามลำดับในสมุดงาน)

### ตารางตรวจก่อนเริ่ม (สามแถวที่ชี้ไปคำตัดสิน)

- **แถว Task 3/4 ↔ Task 5:** หน้าต่างของ Task 5 ใช้ route ของ Task 3–4 ครบ แต่ประวัติการอัปเดตในหน้ารอบต้องมี route อ่านเพิ่ม → คำตัดสิน M1
- **แถว Task 2 เอง:** การสร้างเทอมทั้งสองทางต้องเริ่มรายการงานว่าง ขัดกับ "ทางเดิมไม่เปลี่ยน" และ "ห้ามแก้ tests/py/terms.py" → คำตัดสิน M2

### คำตัดสิน

1. **P1 — ตัวทดสอบลงคาบเพื่อสร้างฉากได้**
   - ตัดสิน: ตัวทดสอบลงคาบผ่าน route เดิมบนสำเนาได้ และต้องคืนตัวแปรของโมดูลทุกตัวเมื่อจบ · ข้อห้าม "ไม่เขียน SLOTS" ผูกโค้ดของโปรแกรม ไม่ใช่ตัวทดสอบ
   - ทำไม: ต้องมีคาบที่ลงไว้จริงจึงทดสอบรายการงานและข้อความผลต่อคาบได้
   - ถ้าผิด: ตัวทดสอบรั่วข้ามกัน — ตัวทดสอบ "ไม่แก้ของเดิม" ท้ายแต่ละไฟล์จับได้

2. **M1 — Task 5 เพิ่ม route อ่านได้หนึ่งตัว**
   - ตัดสิน: เพิ่ม `GET /api/workload/rounds/{id}/plan-updates` (admin อ่านอย่างเดียว) ใน `mock_api.py` ได้ — แผนระบุไว้เอง
   - ทำไม: หน้ารอบต้องแสดงประวัติการอัปเดตกลางเทอม (เมื่อไหร่ · ใคร · ยอมรับ/ไม่ยอมรับกี่ข้อ) ตามแบบข้อ 4.5
   - ถ้าผิด: route อ่านเล็ก ๆ เพิ่มหนึ่งตัว

3. **M2 — สร้างเทอมแล้วรายการงานเริ่มว่าง**
   - ตัดสิน: การเริ่ม `PLAN_TODOS` ว่างตอนสร้างเทอม เป็นการเปลี่ยนเดียวที่ยอมในทางสร้างเทอมเดิม (เพิ่มคีย์ใหม่เท่านั้น) · `tests/py/terms.py` และ `termguard.py` ต้องผ่านโดยไม่แก้
   - ทำไม: รายการงานเป็นของภาคเรียนนั้น (แบบข้อ 4.6) — ข้อของเทอมเก่าไม่ควรตามไปเทอมใหม่
   - ถ้าผิด: ตัวทดสอบทางเดิมต้องเติมคีย์ปลอม

4. **T1 — การตัดสินของเครื่องเทียบ (Task 1)**
   - ตัดสิน:
     - `plan_diff.py` คัดลอกกฎ `_fold_coteaching` และ `_term_keep_set_electives` มาไว้ในตัว (ตัวทดสอบผูกให้เท่าตัวจริง) เพื่อให้เป็นโมดูลฟังก์ชันล้วนและ signature ตรงแผน
     - ช่อง `apply` ของแต่ละข้อ = สิ่งที่จะถูกเขียนพอดี และ token คลุมช่องนี้
     - ช่องในแผนสดที่รอบข้าม นับเป็น "ไม่อยู่ในรอบ"
     - ข้องานครูดูแค่ครูผู้สอนหลัก (ภายหลังขยายเป็นสามช่อง — ข้อ 11)
     - ตัวรันของ `wlexportplan.py` ห่อด้วย `__main__`
   - ทำไม: โมดูลล้วนทดสอบได้โดยไม่ต้องมีเซิร์ฟเวอร์ และ "หน้าเทียบที่เห็น = สิ่งที่ถูกเขียน" ต้องผูกที่ข้อเอง
   - ถ้าผิด: กฎสองสำเนาเพี้ยนจากกัน — ตัวทดสอบเทียบกับตัวจริงจับได้

5. **T1 I1 — แถวที่ชุดของห้องแม่/ห้องย่อยสอนแทน**
   - ตัดสิน: แก้ที่ราก `term_from_round.plan_from_round` (ใช้ทั้งทาง ก. และ ข.): แถวที่ชุดคาบเสรีของห้องแม่หรือห้องย่อยสอนแทน ถูกเขียนกลับเหมือนชุดของห้องตรง · หาชุดที่ครอบไม่เจอ = "ไม่อยู่ในรอบ"
   - ทำไม: ทาง ข. ขึ้น "แถวที่หายไป" เท็จ และ **ทาง ก. ทิ้งแถวเหล่านั้นเงียบ ๆ ตอนสร้างเทอม (บั๊กที่ขึ้นเว็บแล้ว)**
   - ถ้าผิด: ทาง ก. เขียนแถวที่โปรแกรมรู้ว่าถูกสอนแทนอยู่แล้ว — เหมือนแผนเดิม

6. **T1 I2 — แถวที่ชุดสอนแทน เมื่อชุดไม่เปลี่ยน**
   - ตัดสิน: แถวที่ชุดสอนแทนไม่ขึ้นข้อเมื่อชุดที่ครอบไม่เปลี่ยน
   - ทำไม: รอบที่เพิ่งเปิดจากแผนปัจจุบันต้องว่างทุกกอง (ครูในแถวแผนกับครูในชุดต่างกันได้โดยตั้งใจ)
   - ถ้าผิด: การเปลี่ยนครูของแถวที่ถูกสอนแทนโดยชุดที่ไม่เปลี่ยน ต้องแก้เองในโปรแกรม

7. **T1 I3 + m4 — กฎวิชาเสรีของวิชาในชุดอยู่ที่เดียว**
   - ตัดสิน: ย้าย `_term_keep_set_electives` ไป `term_from_round` (`mock_api` เรียกตัวนั้น) · ค่า `is_elective` ที่จะเขียนอยู่ใน `apply`
   - ทำไม: กฎเดียวไม่ต้องคัดลอก
   - ถ้าผิด: ไม่มีราคา

8. **T1 รอบแก้ 1 ข้อกังวล 1 — "ชุดไม่เปลี่ยน" หมายถึงอะไร**
   - ตัดสิน: "ไม่เปลี่ยน" = ครูของชุดที่ครอบ **เฉพาะวิชานั้น** ไม่ใช่ทั้งชุด
   - ทำไม: กฎของทาง ก. อ่านแค่ส่วนนั้นของแถว · ถ้านับทั้งชุด การเปลี่ยนตัวเลือกเดียวของชุดใหญ่จะทำให้ข้อเท็จขึ้นทั่วทั้งชุด
   - ถ้าผิด: การเปลี่ยนส่วนอื่นของชุดที่กระทบแถวนั้นไม่ขึ้นเป็นข้อของแถว (ตัวชุดเองยังขึ้นในกองคาบเสรี/กิจกรรม)

9. **T1 รอบแก้ 1 ข้อกังวล 2 — กฎ "สองห้องมีนักเรียนชุดเดียวกัน"**
   - ตัดสิน: คง `term_from_round.shares_students` เป็นสำเนา ผูกด้วยตัวทดสอบทุกคู่ห้อง · ไม่แตะ `mock_api._shares_students_fn`
   - ทำไม: ตัวนั้นเป็นโค้ดของโปรแกรมจัดตาราง ผู้ใช้ห้ามแตะตรรกะตารางสอน
   - ถ้าผิด: กฎของโปรแกรมเปลี่ยนแล้วต้องแก้สองที่ — ตัวทดสอบทุกคู่จะแดงบอก

10. **T2 — ความหมายของ "ทำแล้ว"**
    - ตัดสิน: สถานะของข้องานที่ตรวจเองได้ (ขาดคาบ · เกินแผน · ยังเป็นครูเดิม) คิดสดจากแผนเทียบคาบเสมอ · "ทำแล้ว" = รับทราบ/ซ่อน ไม่บังคับให้เรียบร้อย · ข้อชนิดคาบเสรี/กิจกรรม (set) ไม่มีเงื่อนไขอัตโนมัติ "ทำแล้ว" = เรียบร้อย
    - ทำไม: แบบข้อ 4.4 "ข้อที่เงื่อนไขหายแล้วขึ้นเรียบร้อยและซ่อนได้" · แผนบรรทัด 41 "set เปิดจนกดทำแล้ว"
    - ถ้าผิด: ผู้ใช้ซ่อนข้อที่ยังค้างไม่ได้ (เห็นค้างจนแก้จริง)

11. **T2 — ข้องานครูครอบสามช่อง**
    - ตัดสิน: ข้องานชนิดครูมีช่อง `fields` ⊆ {ครูผู้สอน, ครูสอนร่วม, ห้องปฏิบัติการ} และตรวจเฉพาะช่องในนั้น
    - ทำไม: แบบให้ครูสอนร่วมและห้องเข้ารายการงานด้วย · หนึ่งข้อต่อหนึ่งห้อง+วิชาทำให้รายการสั้น
    - ถ้าผิด: ต้องเปลี่ยนรูปข้องาน (ตอนตัดสินยังไม่ขึ้นเว็บ)

12. **T2 — บรรทัดผู้ร่วมเขียนในคอมมิต**
    - ตัดสิน: คงชื่อโมเดลของผู้ลงมือในบรรทัด Co-Authored-By ไม่ amend
    - ทำไม: บอกโมเดลที่เขียนจริง และห้ามเขียนประวัติ git ใหม่
    - ถ้าผิด: ไม่มีราคา

13. **T2 m1 → สำคัญ — ตรวจห้องกับทุกคาบของช่อง**
    - ตัดสิน: ยกข้อเล็กนี้เป็นข้อสำคัญ ต้องแก้ก่อนผ่าน
    - ทำไม: ตรวจห้องกับทุกคาบของช่อง → ข้อค้างเท็จที่ "ทำแล้ว" ล้างไม่ได้ (ข้อที่ตรวจเองคิดสดเสมอตามข้อ 10) = ข้อผิดค้างบนจอถาวร
    - ถ้าผิด: เสียหนึ่งรอบแก้เล็ก

14. **T2 m3 — เอาข้อที่ซ่อนกลับมา**
    - ตัดสิน: คง `{"done": false}` ของ `POST /api/terms/todos/{id}/done`
    - ทำไม: Task 5 ใช้ทำปุ่ม "เอากลับมา"
    - ถ้าผิด: ไม่มีราคา (ลบได้ทีหลัง)

15. **T2 — สร้างเทอมแบบไม่เก็บเทอมเดิม แล้วรายการงานหาย**

    - ทำไม: ทางนั้นเกิดเมื่อ `_nothing_a_term_change_would_destroy` (ดูแค่คาบและถาดพัก) เป็นจริง จึงหายได้แค่ข้อคาบเสรี/กิจกรรมของเทอมที่ไม่มีคาบเลย และเทอมใหม่เริ่มรายการว่างอยู่แล้ว (M2 ห้ามแตะทางนี้)

    - ตัดสิน: ตัวเลือกของรอบรับครูเทอมก่อนจากชุดที่ชนิดและห้องตรงกันพอดีก่อน → แล้วชื่อ → ห้องซ้อนกันเป็นทางสุดท้าย (`_wl_prefill_sets`) · รอบที่เปิดไปแล้วคงของที่เก็บไว้
    - ทำไม: เป็นโค้ดของเว็บลงอัตรากำลัง (ไม่ใช่ตารางสอน) และทั้งสองทางเขียนครูผิดจากมัน — **ทาง ก. รวมครูของ pool สองชุดที่ห้องซ้อนกันลง pool ของเทอมใหม่** · ทาง ข. ขึ้นข้อชุดเท็จที่ติ๊กแล้วจะเขียนครูของอีกชุด
    - ถ้าผิด: ห้องคาบเสรีที่ตั้งใจให้ซ้อนกันไม่ได้ครูของอีกชุดเป็นค่าแนะนำ (หัวหน้ากรอกเอง)

19. **T4 I1 — token ผูกกับการอัปเดตครั้งล่าสุด**

    - ทำไม: ปิดการกดซ้อนพร้อมกัน **และ** การกดซ้ำทีหลังด้วยหน้าเดิม ที่ฝั่งเซิร์ฟเวอร์ — รวมข้อที่เข้ารายการงานอย่างเดียวซึ่งไม่เปลี่ยนข้อมูล (ลายนิ้วมือของข้อเฉย ๆ จึงกันไม่ได้)
    - ถ้าผิด: หน้าเทียบที่เปิดไว้ก่อนการอัปเดตครั้งอื่น (รอบไหนก็ได้) ต้องกด "ดูใหม่"

## 2. ข้อเท็จจริงของโค้ดที่ผู้ดูแลคนต่อไปต้องรู้ (เลขบรรทัดเลื่อนได้ ใช้ grep)

### 2.1 กฎเหล็ก: ไม่แตะคาบ
- `SLOTS` และ `PARKED` ไม่อยู่ใน `_PLAN_UPDATE_LISTS` (ตัวแปรที่การอัปเดตแทนและจุดย้อนเก็บ) และไม่อยู่ในผลของ `plan_diff.plan_apply` — ไม่มีคำสั่งใดของทาง ข. เขียนสองตัวนี้
- ตัวทดสอบตรวจซอร์ส `test_new_code_never_writes_slots_or_parked` มีในทั้ง `wlmidtermapply.py` `wlmidtermpreview.py` `wlmidtermtodo.py` · ลองของจริงแล้ว md5 ของคาบและถาดพักเท่าเดิมทั้งในหน่วยความจำและใน `app_state`

### 2.2 token ของหน้าเทียบ (`midterm_token`)
- `diff_token(items)` = sha256 ของรายการข้อที่เรียงตาม `key` และเรียงคีย์ใน dict · ข้อมีช่อง `apply` (สิ่งที่จะถูกเขียน) token จึงคลุมสิ่งที่จะเขียนด้วย
- ผูกกับรหัสแถวล่าสุดของ `wl_plan_updates` ของ **ทั้งฐาน** (`SELECT id … ORDER BY id DESC LIMIT 1`): ไม่มีแถว = `diff_token` · มี = sha256(`"<diff_token>:<รหัสล่าสุด>"`)
- POST คำนวณหน้าเทียบใหม่ในธุรกรรม **หลังได้ล็อก** แล้วเทียบ — ไม่ตรง = 409 "ข้อมูลเปลี่ยนตั้งแต่เปิดหน้าเทียบ — ดูใหม่อีกครั้ง"
- ผล: การอัปเดตครั้งใดก็ตามหลังเปิดหน้าเทียบทำให้หน้านั้นเก่า → กดซ้อน/กดซ้ำไม่มีทางเขียนซ้ำ · token เท่าเดิมทุกไบต์หลังเริ่มเซิร์ฟเวอร์ใหม่ (รีวิวทั้งสาขาลองแล้ว) — Render เริ่มใหม่ระหว่างดูกับกดไม่ทำให้ได้ 409 เปล่า ๆ

### 2.3 ลำดับในธุรกรรมของ `POST /api/terms/plan-update` (`_plan_update_transaction` · คอมเมนต์หัวส่วนใน `mock_api.py`)
1. ก่อนเปิดธุรกรรม:
   - ตรวจรูปคำขอ (ไม่ติ๊กเลย = 400 ไม่ตรวจรหัส)
   - ตรวจรหัสผู้ดูแลระบบ (นับครั้งผิดร่วมกับหน้าล็อกอิน)
   - เทอมที่เปิดอยู่ปิดแล้ว = 409 (`term_closed_message` ตัวเดียวกับมิดเดิลแวร์ — `/api/terms/` ไม่ถูกมิดเดิลแวร์กัน)
   - ข้อมูลของโรงเรียนยังโหลดไม่สำเร็จ = 503
   - ล้างคิวเซฟ
2. การเชื่อมต่อเดียว: ล็อกทะเบียน (advisory lock) เป็นคำสั่งแรก → แถวรอบ `FOR UPDATE` — ลำดับเดียวกับทาง ก.
3. จดตัวนับรุ่น (`REVISION`) → `_midterm_build(keep_live=True)` (ตัวประกอบเดียวกับหน้าเทียบ GET):
   - เหตุของรอบ = 409
   - token ไม่ตรง = 409
4. ใส่:
   - เก็บจุดย้อน
   - เทียบรุ่น
   - `plan_apply` ใส่จาก `item["apply"]` เท่านั้น ลงสำเนาของสดชุดเดียวกับที่เทียบ
   - แทนตัวแปรในที่ (`[:] =`)
5. บันทึก:
   - เขียน `sched_id` กลับทะเบียน
   - INSERT `wl_plan_updates` (ได้ `update_id`)
   - ข้องานได้รหัส
   - UPSERT `app_state` เป็นสำเนาสดในธุรกรรม (ต้องหลังข้องาน — สำเนาต้องมี update_id)
   - รอบที่เปิดให้แก้กลางเทอม → ปิดกลับ
6. เทียบรุ่นอีกครั้ง (มีคนแก้โปรแกรมระหว่างนั้น = 409) → **COMMIT ครั้งเดียว**
   - ล้มก่อน COMMIT = คืนตัวแปรก่อน ROLLBACK (ยังถือล็อก) → 409/500 ไทย
7. หลัง COMMIT: บันทึกประวัติเทอม · ล้างแคช · เซฟ

- จุดฉีดล้ม `SCHED_TEST_FAIL_AT`:
  - ล้มที่ขั้นนั้น: `plan_built` `plan_apply` `plan_writeback` `plan_history` `plan_app_state` `plan_round` `plan_commit`
  - `plan_after_commit` = ฆ่า process หลัง COMMIT
  - `wait:<ขั้น>` = หน่วงที่ขั้นนั้น
  - production ไม่ตั้งตัวแปรนี้

### 2.4 `already_todo` (`plan_diff.split_listed`)
- ดูเฉพาะข้อที่ `apply.op == "todo"` (เข้ารายการงานอย่างเดียว: ชุดที่ลงคาบแล้ว · ชุดจากช่องรายห้อง · กิจกรรม)
- ข้องานที่สร้างจากข้อ = `set_todo(item)` ตัวเดียวกับที่ `plan_apply` ใช้ · เทียบด้วย (kind, group_id, subject_id, text) กับข้องานที่ `done` เป็นเท็จ
- ข้อที่เปลี่ยนข้อมูล **และ** สร้างข้องาน (เช่นสร้าง pool ใหม่ + "ลงคาบ") ไม่ถูกย้ายเด็ดขาด
- กด "ทำแล้ว" ที่ข้องานทั้งที่ปัญหายังอยู่ → ข้อกลับมาให้ติ๊กได้ (ตามคำตัดสินข้อ 20)

### 2.5 ข้องาน (`PLAN_TODOS`) และช่อง `fields`
- รูป `{id, update_id, kind: missing|over|teacher|set, group_id, subject_id, teacher_id?, fields?, text, done}` · เก็บในสแนปช็อตคีย์ `plan_todos` (ติดไปกับไฟล์เทอมและสำรอง)
- สร้างเทอมใหม่ (ทั้งสองทาง) = ว่าง · ปลดล็อกเทอม = รายการของเทอมนั้น (ไม่มีคีย์ = ว่าง ไม่ใช่คงของเดิม)
- สถานะสด `todo_status`: missing/over นับคาบที่ลงของ (ห้อง, วิชา) เทียบคาบตามแผน
- teacher:
  - จับคาบแต่ละคาบกับแถวแผน **ทั้งแถว** ครั้งเดียวต่อคาบ (คู่สอนร่วมเทียบเป็นคู่ ไม่สนลำดับ) แล้วรายงานเฉพาะช่องใน `fields`
  - ห้องตรวจเฉพาะเมื่อแถวแผนกำหนดห้อง
  - ไม่มีแถวแผนแล้ว = เรียบร้อย
- set: เปิดจนกด "ทำแล้ว"
- `POST /api/terms/todos/{id}/done` แตะแค่ช่อง `done` · body `{"done": false}` = เอากลับมา · เทอมที่เปิดอยู่ปิดแล้ว = 409

### 2.6 รอบที่เปิดให้แก้กลางเทอม (`wl_rounds.amending_since`)
- `POST /api/workload/rounds/{id}/amend` (admin):
  - ทำได้เฉพาะรอบที่ปิดแล้ว ของภาคเรียนที่เปิดอยู่ในโปรแกรม และไม่มีรอบอื่นที่ยังไม่ปิด
  - ผล: รอบ closed → filling · **ทุกกลุ่มสาระ → กำลังกรอก** · `amending_since = now()`
- ตัวกันรอบที่ส่งแล้ว (`wl_round_exported_refusal`) ยอมรอบที่ `amending_since` ไม่ว่าง · ทาง ก. ยังส่งรอบนั้นซ้ำไม่ได้ (`wl_export_reasons`)
- `amending_since` ถูกล้างเมื่อ: อัปเดตแผนสำเร็จ (รอบปิดกลับ) · admin ปิดรอบ · ทาง ก. ส่งรอบ
- เกณฑ์ใช้ได้ของทาง ข. = เกณฑ์ของทาง ก. ยกเว้น "ยังไม่เคยส่ง" และ "ยังไม่มีเทอมนี้" + ปี/ภาคต้องตรงภาคที่เปิดอยู่ (`_term_running_identity`):
  - จึง **รอบที่ปิดแล้วใช้ได้ทันที**
  - รอบที่เปิดให้แก้ใช้ได้เมื่อทุกกลุ่มตรวจผ่าน หรือปิดรอบอีกครั้ง (คู่มือข้อ 11ก ขั้นที่ 3)

### 2.7 ทะเบียนตอนปลดล็อกเทอม
- `wl_writeback_history` รวมการเขียน `sched_id` กลับของทั้งการส่งทาง ก. (`export_report`) และการอัปเดตกลางเทอม (`wl_plan_updates.report.writeback`) เรียงตามเวลา แล้ว `wl_registry_reconcile` ปรับเทียบ
- ไม่มีแถวใน `wl_plan_updates` = ทางเดิมทุกคำสั่ง (ตัวทดสอบผูกไว้)
