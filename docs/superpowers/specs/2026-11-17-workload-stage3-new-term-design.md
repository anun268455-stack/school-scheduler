## 1. เจตนา

ทุกภาคเรียน ฝ่ายวิชาการต้องพิมพ์แผนการสอนทั้งเทอม (ห้อง × วิชา × ครู × คาบ ราว 1,200 แถว) และคาบเสรีลงโปรแกรมจัดตารางใหม่
ทั้งที่ข้อมูลชุดเดียวกันถูกกรอกและตรวจแล้วในเว็บลงอัตรากำลัง ขั้นนี้ทำให้ตอนกด **"สร้างเทอมใหม่"** ในโปรแกรมจัดตาราง
admin เลือก **รอบอัตรากำลังของภาคเรียนนั้นที่ตรวจผ่านแล้ว** ได้ แล้วเทอมใหม่เริ่มต้นด้วยแผนการสอน คาบเสรี
และหลักสูตรตามรอบนั้นครบ ครูและวิชาใหม่ถูกสร้างในโปรแกรมให้ — **ตารางเริ่มว่างเหมือนเดิม** แล้วไปจัดคาบตามปกติ

ผู้ใช้เลือก "ก." (16–17 พ.ย.): ทำทางเข้าสร้างเทอมใหม่ก่อน เพราะช่วยงานมากที่สุดตอนขึ้นภาคเรียนหน้า
และไม่มีทางกระทบตารางสอนที่เพิ่งจัดเสร็จ · ทาง "ข." (อัปเดตกลางเทอมแบบเทียบสี่กอง) เป็นงานถัดไป ไม่อยู่ในแบบนี้

## 2. เป้าหมาย / ไม่ทำ / ห้ามเกิด

**เป้าหมาย**
1. หน้าต่างสร้างเทอมใหม่มีทางเลือกแหล่งของแผน: **แผนเดิมของเทอมนี้** (แบบที่ทำอยู่ตอนนี้ — ไม่เปลี่ยนพฤติกรรม) หรือ **รอบอัตรากำลัง**
2. ก่อนกดยืนยัน เห็นสรุป: แผนการสอนกี่แถว · คาบรวม · ครูในแผนกี่คน · **ครูใหม่ที่จะสร้าง** · **วิชาใหม่ที่จะสร้าง** ·
   ครู/วิชาที่จะแก้ชื่อหรือกลุ่มสาระ · ชุดคาบเสรี/ตัวเลือก · ชุดกิจกรรมที่ต้องลงคาบเอง · ครูฝั่งโปรแกรมที่เว็บไม่รู้จัก (อ่านอย่างเดียว) ·
   และ **เหตุที่ยังสร้างไม่ได้** (ถ้ามี) — แสดงอย่างเดียว ไม่เขียนอะไร
3. ยืนยันต้องกรอก **รหัสผู้ดูแลระบบของเว็บลงอัตรากำลัง** ซ้ำ (สเปกหลักส่วนที่ 3)
4. **ทั้งหมดหรือไม่มีเลย** — ล้มกลางทางแล้วโปรแกรมจัดตาราง ฐานข้อมูล และเว็บลงอัตรากำลังกลับเป็นเหมือนก่อนกดทุกอย่าง
5. รอบที่ส่งแล้วถูกทำเครื่องหมาย **"ส่งเข้าโปรแกรมแล้ว (เทอม …)"** อ่านอย่างเดียวถาวร ส่งซ้ำไม่ได้
6. ครู/วิชาที่สร้างใหม่ได้รหัสของโปรแกรมกลับไปเก็บในทะเบียนของเว็บ (`sched_id`) — กดรอบหน้าไม่สร้างซ้ำ

**ไม่ทำในขั้นนี้**
- อัปเดตกลางเทอม (ทาง ข.) · รายการ "คาบที่ต้องไปแก้เอง" ในโปรแกรม (เป็นของทาง ข.)
- ลงคาบให้ (คาบเสรี กิจกรรม หรืออะไรก็ตาม) — ตารางเริ่มว่าง คนจัดคาบเหมือนเดิม
- ลบครูหรือวิชาในโปรแกรม · ส่งสถานะ "ไม่ปฏิบัติงานแล้ว" ไปปิดครูในโปรแกรม (ข้อ 4.3)
- ช่องที่โปรแกรมเป็นเจ้าของ (ห้องประจำ คาบสูงสุด/วัน วันที่ไม่สอน ฯลฯ — สเปกหลักส่วนที่ 4)
- ล็อกหน้าครู/วิชาฝั่งโปรแกรม

**ห้ามเกิด (ถ้าเกิดถือว่าล้มเหลวแม้อย่างอื่นทำงาน)**
- ข้อมูลของ **เทอมที่ถูกปิด** ต่างจากที่ปุ่มสร้างเทอมใหม่แบบเดิมจะเก็บไว้ แม้แต่ไบต์เดียว
- เทอมใหม่ครึ่ง ๆ กลาง ๆ (แผนมาแต่ครูไม่มา · เทอมสร้างแล้วแต่รอบยังไม่ถูกทำเครื่องหมาย ฯลฯ)
- ครูหรือวิชาซ้ำในโปรแกรมเพราะกดสองครั้ง หรือเพราะล้มแล้วลองใหม่
- ช่องเงื่อนไขของครูที่มีอยู่แล้วเปลี่ยน (สเปกหลักข้อทดสอบ 10ก)
- ส่งรอบที่ยังมีรายการไม่มีครูหรือยังไม่ยืนยัน
- โค้ดใหม่เขียนคาบ (`SLOTS`) — ขั้นล้างคาบของปุ่มเดิมเป็นที่เดียวที่แตะ และไม่เปลี่ยน

## 3. ข้อผูกมัด

- ข้อห้ามของผู้ใช้ทั้งหมดใน `docs/HANDOFF.md` ยังมีผล — โดยเฉพาะ "ห้ามกดสร้างเทอมใหม่บนเว็บจริงจนขึ้นภาคเรียนถัดไป"
  การทดสอบทั้งหมดทำกับ Postgres ทดลองในเครื่องพัฒนา
- การเขียน `TEACHERS` `SUBJECTS` `REQUIREMENTS` `ELECTIVE_POOLS` `CURRICULA` และกลุ่มเรียน ทำ **ภายในคำขอ `POST /api/terms` เท่านั้น**
  (ผ่านตัวนับรุ่นและการเซฟสแนปช็อตตามปกติ) — route ใต้ `/api/workload/` ยังห้ามแตะของเหล่านี้ (คอมเมนต์ที่ `WORKLOAD_PREFIX`)
- ไม่เพิ่ม dependency · ข้อความที่ผู้ใช้เห็นเป็นไทยทั้งหมด · อ้างครู/วิชาด้วยรหัสเท่านั้น ไม่จับคู่ด้วยชื่อ
- ห้ามสร้าง unique index ใหม่บนตารางที่มีข้อมูลจริง (`wl_*` ขั้นที่ 1–2) · เพิ่มคอลัมน์ได้ด้วย `ADD COLUMN IF NOT EXISTS`
- งานนี้แก้ `frontend/` ได้ **เฉพาะ** หน้าต่างสร้างเทอมใหม่และตัวเรียกเซิร์ฟเวอร์ของมัน (`components/terms/`, `utils/terms.ts`,
  `api/client.ts`, `store/timetableStore.ts` ส่วน `makeNewTerm`) — ไม่แตะหน้าจัดคาบ
- พฤติกรรมของ "สร้างเทอมใหม่จากแผนเดิม" ต้องเหมือนเดิมทุกอย่าง (ตัวทดสอบเดิมของชั้นเทอมต้องผ่านโดยไม่แก้)

## 4. สิ่งที่ตัดสินแล้ว

### 4.1 รอบไหนใช้ได้

รอบใช้ได้เมื่อ **ทุกข้อ** จริง (ตรวจตอนดูสรุปและตรวจซ้ำในธุรกรรมตอนยืนยัน):
1. ปี/ภาคเรียนของรอบ **ตรงกับเทอมใหม่** — เลือกรอบแล้วช่องปี/ภาคเรียนถูกตั้งตามรอบและล็อก
2. สถานะรอบเป็น `filling` หรือ `closed` และ **ยังไม่เคยส่ง**
3. ทุกกลุ่มสาระที่มีรายการในรอบอยู่สถานะ `approved` และผ่าน `wl_approve_blocker` ณ ตอนนั้น
   (ครบครูและยืนยันครบ — admin แก้หลังตรวจผ่านได้ จึงต้องตรวจซ้ำ) · กลุ่มที่ไม่มีรายการไม่นับ
4. ทุกแถว/ตัวเลือกอ้างวิชาที่มีรหัสวิชา และทุกครูที่ถูกอ้างยังมีอยู่ในทะเบียนของเว็บ

ไม่ผ่าน → สรุปขึ้นรายการเหตุ (เช่น "กลุ่มสาระคณิตศาสตร์ยังไม่ตรวจผ่าน" · "ยังไม่ยืนยัน 3 รายการ ในกลุ่มสาระ…") และปุ่มยืนยันกดไม่ได้

ส่งแล้ว: ถ้ารอบยัง `filling` จะถูกปิด (`closed`) ในธุรกรรมเดียวกัน และบันทึก `exported_at` · `exported_term_id` · `exported_label` ·
`export_report` (สรุปตัวเลขและรายการที่ต้องทำเอง) ในแถวรอบ · หน้าเว็บลงอัตรากำลังแสดง "ส่งเข้าโปรแกรมแล้ว — เทอม …"

### 4.2 แปลงอะไรเป็นอะไร

| ของเว็บลงอัตรากำลัง | ไปเป็น (เทอมใหม่) | กฎ |
|---|---|---|
| แถวของรอบ (หนึ่งห้อง × หนึ่งบรรทัดหลักสูตร) | หนึ่งแถว `REQUIREMENTS` | `group_id` · `subject_id` = sched id ของวิชาในบรรทัด · `teacher_id` · `co_teacher_id` (ครูสอนร่วม หรือว่าง) · `weekly_count` = คาบ/สัปดาห์ของบรรทัด · `room_id` = ห้องปฏิบัติการ (ว่างได้) · `pinned_double` = คาบคู่ (ใส่เฉพาะเมื่อจริง) |
| ช่องที่เว็บไม่มี: `parallel_group_key` (เซ็ตห้องย่อย) · `pinned_day` · `pinned_period` | **ยกมาจากแผนเดิมของเทอมที่กำลังปิด** | เมื่อแผนเดิมมี **แถวเดียว** ที่ (ห้อง, วิชา) ตรงกัน → ยกสามช่องนี้มา · ไม่ตรงหรือมีหลายแถว → ว่าง (นับและบอกในสรุป) |
| ชุดคาบเสรี (`wl_term_sets` kind `elective`) | หนึ่ง `ELECTIVE_POOLS` | `name` · `group_ids` · `weekly` · `is_double` · **ยังไม่ลงคาบ** (`day`/`period` ว่าง) · ตัวเลือก = หนึ่งต่อ (ตัวเลือก, ครู) — ตัวเลือกที่มีครูสองคนเป็นสองตัวเลือก ตามรูปที่โปรแกรมเก็บอยู่ · `room_id` จากครูของตัวเลือก · วิชาของตัวเลือกถูกติดธงวิชาเสรี (`_mark_elective`) · **ไม่สร้างแถวแผนให้วิชาในคาบเสรี** (ตรงกับข้อมูลปัจจุบันที่มี 0 แถว) |
| ชุดกิจกรรม (kind `activity`) | **ไม่มีที่ปลายทาง** | โปรแกรมเก็บกิจกรรมไว้ในคาบเท่านั้น (ตารางเริ่มว่าง) → ขึ้นในสรุปและในรายงานผลเป็น "ชุดกิจกรรมที่ต้องลงคาบเอง: ชื่อ · ห้อง · คาบ/สัปดาห์ · ครูที่คุม" · บรรทัดหลักสูตรประเภทกิจกรรมที่เป็นแถวธรรมดา (มีครูรายห้อง) ไปเป็นแถวแผนตามแถวแรก |
| หลักสูตรของภาคเรียน (`wl_curricula` + บรรทัด + ห้อง) | แทน `CURRICULA` ของโปรแกรม และ `curriculum_id` ของห้อง | หนึ่งหลักสูตรต่อหนึ่ง `wl_curricula`: ชื่อเดิม · `rows` = (sched id ของวิชา, คาบ/สัปดาห์) ของบรรทัด (ซ้ำ → ค่ามากสุด ตาม `normalise_rows`) · ห้องที่ไม่อยู่ในหลักสูตรใดของภาคเรียน → `curriculum_id` ว่าง |
| ความเห็น `note` · `flag` · `confirmed` · `from_plan` | ไม่ไปไหน | เก็บอยู่ในรอบที่ปิดแล้ว ดูย้อนหลังได้ |

แผนเดิม คาบเสรีเดิม และหลักสูตรเดิมของโปรแกรม **ถูกแทนทั้งชุด** ในเทอมใหม่ (เทอมที่ปิดเก็บของเดิมไว้ครบในไฟล์เทอม)

### 4.3 ซิงก์ทะเบียนครูและวิชา (ทำก่อนแผนเสมอ — สเปกหลักส่วนที่ 7)

> เพิ่มใหม่กับแก้ช่องตัวตนเท่านั้น ไม่ลบอะไรเลย

| กรณี | ทำอะไร |
|---|---|
| ครูในทะเบียนของเว็บที่ **ยังปฏิบัติงาน** และยังไม่มี `sched_id` (หรือ `sched_id` ชี้ไปครูที่ไม่มีในโปรแกรมแล้ว) | สร้างครูใหม่ในโปรแกรม ด้วยค่าตั้งต้นเดียวกับ `/api/teachers/bulk` (คาบสูงสุด/วัน 6 · คะแนนกลางแจ้ง 5 · กลางแจ้งสูงสุด/สัปดาห์ 2 · ไม่มีห้องประจำ) แล้วเก็บรหัสกลับเป็น `sched_id` |
| ครูที่มีทั้งสองฝั่ง แต่ **ชื่อ · รหัสประจำตัว · กลุ่มสาระ · ลำดับในกลุ่ม** ต่างกัน | แก้เฉพาะช่องที่ต่างในโปรแกรม (ช่องอื่นของครูต้องเท่าเดิมทุกช่อง) |
| ครูที่เว็บทำเครื่องหมาย "ไม่ปฏิบัติงานแล้ว" | **ไม่ส่งไปปิดในโปรแกรม** (สถานะเปิด/ปิดไม่อยู่ในช่องที่เว็บเป็นเจ้าของ) — ขึ้นในสรุปให้อ่าน "ไม่ปฏิบัติงานแล้วในเว็บ แต่ยังเปิดอยู่ในโปรแกรม N คน" · ครูที่ไม่ปฏิบัติงานและไม่มี `sched_id` ไม่ถูกสร้าง |
| ครูที่โปรแกรมมี แต่เว็บไม่รู้จัก | ไม่ทำอะไร ขึ้นในสรุปให้อ่าน |
| วิชา | กฎเดียวกัน · ช่องที่แก้: รหัส · ชื่อ · ประเภท · กลุ่มสาระ · คาบคู่ (`duration`) · เป็นกิจกรรม · เป็นวิชาเสรี · วิชาใหม่ใช้ค่าตั้งต้นของ `/api/subjects/bulk` และได้ `credits` จากบรรทัดหลักสูตรที่อ้างถึง (ค่าแรกตามลำดับหลักสูตร) |
| บรรทัดหลักสูตร/ตัวเลือกที่พิมพ์รหัสเองแต่ไม่ผูกวิชาในทะเบียน (`subject_id` ว่าง) | สร้างวิชาในทะเบียนของเว็บ **และ** ในโปรแกรม (รหัส ชื่อ กลุ่มสาระ จากบรรทัด) แล้วผูกบรรทัด/ตัวเลือกนั้น — สองบรรทัดที่พิมพ์รหัสเดียวกันได้วิชาเดียวกัน · รหัสชนกับวิชาในทะเบียนของเว็บที่มีอยู่ → ผูกกับวิชานั้นแทนการสร้าง |

### 4.4 ทั้งหมดในธุรกรรมเดียว

ลำดับในคำขอ `POST /api/terms` เมื่อมี `round_id`:
1. ตรวจรูปคำขอ · ตรวจรหัส admin ของเว็บลงอัตรากำลัง (นับครั้งผิดร่วมกับการล็อกอินของเว็บ) · ตรวจเหมือนปุ่มเดิมทุกข้อ (ปีซ้ำ · เขียนฐานไม่ได้ ฯลฯ)
2. เปิด **การเชื่อมต่อฐานข้อมูลเดียว** เริ่มธุรกรรม · ล็อกแถวรอบ `FOR UPDATE` ก่อนอ่านอะไรของรอบ
   (การเขียนของหัวหน้า/admin ทุกทางล็อกแถวรอบก่อน จึงต่อคิวกันเอง ไม่มีใครแก้รอบระหว่างนี้)
3. อ่านรอบ หลักสูตร ชุด ทะเบียน ทั้งหมดในธุรกรรมนั้น → ตรวจข้อ 4.1 ซ้ำ → คำนวณ **สถานะใหม่ทั้งชุดเป็นสำเนา** ด้วยฟังก์ชันล้วน
   (ยังไม่แตะตัวแปรของโปรแกรม)
4. เก็บสำเนาเพื่อย้อนของทุกตัวแปรที่จะแตะ (`TEACHERS` `SUBJECTS` `REQUIREMENTS` `ELECTIVE_POOLS` `CURRICULA` `curriculum_id` ของห้อง
   ตัวนับรหัส `SLOTS` `PARKED` `CURRENT_TERM` `SCHOOL_CONFIG`)
5. ทำตามปุ่มเดิม: **บรรจุเทอมเก่าก่อน** (ไฟล์เทอมเก่าจึงเหมือนปุ่มเดิมทุกไบต์) → ล้างคาบ
6. ใส่สถานะใหม่ (ครู/วิชาใหม่ได้รหัสจากตัวนับ · แก้ช่องตัวตน · แทนแผน คาบเสรี หลักสูตร) → บรรจุไฟล์เทอมใหม่
7. ในธุรกรรมเดียวกัน: หมุนเทอม (ปิดเก่า เปิดใหม่) · เขียน `sched_id` กลับ · สร้างวิชาในทะเบียนของเว็บและผูกบรรทัด ·
   ทำเครื่องหมายรอบว่าส่งแล้ว → **COMMIT ครั้งเดียว**
8. ล้มที่ขั้นใดก่อน COMMIT → ROLLBACK ฐาน + คืนตัวแปรทุกตัวจากขั้น 4 → ตอบ 500/409 ไทย "ข้อมูลเดิมยังอยู่ครบ"
9. หลัง COMMIT ทำเหมือนปุ่มเดิม (บันทึกประวัติเทอม · เซฟ · ตัวนับรุ่น) และล้างค่าที่อ้างแผนเก่า (`LAST_RUN` · แคชชื่อ)

ปุ่มแบบเดิม (ไม่มี `round_id`) เดินทางเดิมทุกขั้น ไม่ผ่านโค้ดใหม่

- ไม่มีรอบเลย → ไม่แสดงทางเลือก หน้าต่างเหมือนเดิมทุกอย่าง

- ข้อผิดพลาดจากเซิร์ฟเวอร์แสดงข้อความไทยของเซิร์ฟเวอร์ตามแบบเดิมของหน้าต่าง · การกดซ้ำ/หมดเวลาใช้กลไกกันกดซ้ำเดิม

### 4.6 route ใหม่ (ทั้งหมดอยู่ฝั่งโปรแกรมจัดตาราง ไม่มีการล็อกอินเหมือน route อื่นของโปรแกรม)

- `GET /api/terms/rounds` → รอบทั้งหมด (ใหม่ก่อน) `{id, label, year, semester, status, exported_at, exported_label, usable, reasons[]}` —
  ไม่มีข้อมูลรายแถว
- `GET /api/terms/preview?round_id=` → ตัวเลขเดิม 5 ตัว + ตัวเลขของรอบ (ข้อ 4.5) + รายการ (ชุดกิจกรรม · ครูที่โปรแกรมมีแต่เว็บไม่รู้จัก ·
  ครูที่จะสร้าง · วิชาที่จะสร้าง · ที่จะแก้) + `reasons[]` · ไม่เขียนอะไร · ใช้ฟังก์ชันคำนวณเดียวกับตอนยืนยัน
- `POST /api/terms` รับเพิ่ม `round_id` และ `admin_code` (ไม่ส่ง `round_id` = ทางเดิม)
- เว็บลงอัตรากำลัง: รูปรอบ (`GET /api/workload/rounds…`) เพิ่ม `exported_at` · `exported_label` · `export_report`

### 4.7 ฐานข้อมูล

`wl_rounds` เพิ่มคอลัมน์ (`ADD COLUMN IF NOT EXISTS`): `exported_at timestamptz` · `exported_term_id` · `exported_label text` ·
`export_report jsonb` — ไม่มี index ใหม่ · รอบที่ส่งแล้วถือว่าปิดถาวร (ทุก route เขียนของรอบปฏิเสธ 409 ไทยเหมือนรอบปิด
และ route ยกเลิกรอบ/ปิดรอบไม่ใช้กับรอบนี้)

## 6. ทดสอบก่อนปล่อย (เพิ่มจากสเปกหลักส่วนที่ 11)

1. **ไปกลับครบรอบบนข้อมูลตั้งต้น**: แผนเดิม → ตั้งต้นหลักสูตร → เปิดรอบ → ยืนยันทุกแถว (bulk) → ตรวจผ่านทุกกลุ่ม → สร้างเทอมจากรอบ →
   แผนใหม่ **เท่ากับแผนเดิม** ในรูป (ห้อง, วิชา, ครู, ครูสอนร่วม, คาบ/สัปดาห์, room_id) เป็นหลายเซต (ยกเว้นแถวที่ขั้นที่ 2 แปลงไม่ได้ซึ่งต้องบอกได้ว่าเพราะอะไร)
   และคาบเสรี 13 ชุด 44 ตัวเลือกตรงกับเดิม
2. ไฟล์เทอมที่ถูกปิด **เท่ากับ** ที่ปุ่มแบบเดิมสร้างจากสถานะเดียวกัน (เทียบ JSON หลังคลาย)
3. ฉีดความล้มเหลวทุกขั้นหลังบรรจุเทอมเก่า (ระหว่างใส่ · ระหว่างบรรจุใหม่ · ระหว่างหมุน · ระหว่างเขียนกลับ · ตอน COMMIT) → ตัวแปรของโปรแกรม
   ทุกตัวเท่าก่อนกด · ฐานไม่มีเทอมใหม่ · รอบยังไม่ถูกทำเครื่องหมาย · `sched_id` ไม่เปลี่ยน
4. กดซ้ำ/ส่งรอบเดิมอีก → 409 ไทย ไม่มีอะไรถูกสร้าง · สองคำขอพร้อมกัน → หนึ่งสำเร็จ หนึ่ง 409 (ลองกับ Postgres จริงสองเซสชัน)
5. ครูที่แก้ชื่อในเว็บ → ช่องอื่นของครูคนนั้นในโปรแกรมเท่าเดิมทุกช่อง (10ก) · วิชาที่พิมพ์รหัสเองถูกสร้างหนึ่งครั้ง แม้หลายบรรทัดอ้าง (ข้อ 5 สเปกหลัก)
6. รอบที่ยังไม่ผ่านทุกเหตุในข้อ 4.1 → สรุปบอกเหตุ ปุ่มกดไม่ได้ · ยิงตรงก็ 409
7. รหัส admin ผิด → 403 ไม่มีอะไรเกิด · ผิดเกินเกณฑ์ → ถูกจำกัดเหมือนล็อกอิน
8. ปุ่มแบบเดิม: ตัวทดสอบเดิมของชั้นเทอม (`tests/py/terms.py` `termguard.py`) ผ่านโดยไม่แก้ · และบน Postgres จริงได้ผลเท่าก่อนงานนี้
9. หลังสร้าง: หน้าจัดคาบเปิดได้ แผนใหม่แก้ผ่านหน้าเดิมได้โดยไม่ถูกปฏิเสธเรื่องหลักสูตร (`check_row`) · สั่งจัดคาบอัตโนมัติรันได้
10. ลองอัปเกรด: เซิร์ฟเวอร์รุ่นบน `main` → รุ่นใหม่บนฐานเดียวกัน (คอลัมน์ใหม่ถูกเพิ่ม ของเดิมครบ)

## 7. ปล่อยใช้

merge ผ่าน PR แบบขั้นที่ 1–2 (นอกเวลาเรียน) · คู่มือ `docs/workload-setup.md` เพิ่มหัวข้อ "ขึ้นภาคเรียนใหม่ด้วยรอบอัตรากำลัง"
