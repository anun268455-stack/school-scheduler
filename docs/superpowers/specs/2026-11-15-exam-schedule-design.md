# ระบบจัดตารางสอบ — แบบร่าง

วันที่ 15 พฤศจิกายน 2569 · **รอผู้ใช้ตรวจ** · ยังไม่เริ่มเขียนโปรแกรม

---

## ผมอ่านโจทย์ว่าอย่างไร

ผู้ใช้สั่งว่า *"ทำโปรเจกจัดตารางสอบที่[โยง]กับอัตรากำลังได้เลย เอาแบบสมบูรณ์เลยนะ
พร้อมกับตารางรหัสเข้าของแต่ละหมวดเลย"* แล้วตอบว่า **"ทำเลย"** เมื่อถามเรื่องปลายทาง

ผมถามไปสองครั้งว่าตารางสอบที่ต้องการสุดท้ายออกมาเป็นอะไร และยังไม่ได้คำตอบ จึงเลือก
อ่านแบบกว้างที่สุดตามคำว่า "สมบูรณ์" คือ **ทำครบตั้งแต่จัดวันสอบ จัดห้องสอบ จัดครูคุมสอบ
ไปจนถึงใบพิมพ์ทั้งของนักเรียนและของครู**

> **ถ้าอ่านผิด ข้อนี้คือข้อที่ต้องแก้ก่อนทุกข้อ** ถ้าที่จริงต้องการแค่ "ตารางว่าวิชาไหนสอบวันไหน"
> งานจะเล็กลงเหลือราวหนึ่งในสี่ และไม่ต้องมีเรื่องที่นั่งกับเวรคุมสอบเลย

## สิ่งที่ค้นแล้วพบ

| เรื่อง | สถานะจริงในโค้ด |
|---|---|
| ตารางสอบ ห้องสอบ คุมสอบ | **ไม่มีอะไรเลยสักบรรทัด** ค้นทั้ง repo แล้ว |
| ความจุห้อง | มี — `Room.capacity` |
| จำนวนนักเรียนต่อห้องเรียน | มี — `StudentGroup.size` |
| วิชาที่แต่ละห้องเรียนเรียน และใครสอน | มี — แผนการสอน (`LessonRequirement`) |
| กลุ่มสาระ อาคาร ชั้นเรียน | มีครบ |
| รหัสเข้าของแต่ละกลุ่มสาระ | **มีแล้ว** ตาราง `wl_codes` หนึ่งรหัสต่อหนึ่งกลุ่มสาระ บังคับด้วยดัชนีในฐานข้อมูล |

**ตารางรหัสเข้าที่สั่งมาด้วย ไม่ต้องทำใหม่** มันถูกสร้างไว้แล้วตอนทำเว็บลงอัตรากำลังใน
Claude Code พร้อมหน้าตั้งรหัสและคู่มือ สิ่งที่ค้างคือมันยังไม่ได้ขึ้นเว็บ (ดูหัวข้อสุดท้าย)

## ทำไมเครื่องจัดตารางเรียนตัวเดิมใช้ต่อไม่ได้

ตารางเรียนกับตารางสอบเป็นคนละโจทย์ ไม่ใช่โจทย์เดียวกันคนละขนาด

| | ตารางเรียน | ตารางสอบ |
|---|---|---|
| ช่วงเวลา | ทั้งเทอม 5 วัน × 9 คาบ วนซ้ำทุกสัปดาห์ | 3–5 วัน ไม่วนซ้ำ วันละ 2–3 ช่วง ช่วงละ 1–2 ชั่วโมง |
| ห้อง | ห้องประจำชั้นและห้องเฉพาะวิชา | ห้องไหนก็ได้ที่นั่งพอ แบ่งห้องเรียนหนึ่งห้องออกเป็นหลายห้องสอบได้ |
| คนในห้อง | ครูผู้สอนวิชานั้น | ครูคุมสอบ ซึ่งมักจงใจไม่ใช่ครูผู้สอนวิชานั้น |
| ข้อห้ามหลัก | ครู/ห้อง/ชั้น ชนกัน | ทั้งระดับชั้นสอบวิชาเดียวกันพร้อมกัน และนักเรียนคนหนึ่งสอบสองวิชาพร้อมกันไม่ได้ |

เขียนเครื่องจัดใหม่ แยกจากของเดิม ไม่แตะเครื่องเดิมเลย

---

## ขอบเขต

**ทำ**

1. ตั้งช่วงสอบ — วันไหนบ้าง วันละกี่ช่วง ช่วงละกี่นาที
2. เลือกว่าวิชาไหนต้องสอบ แยกตามระดับชั้น (ตั้งต้นจากแผนการสอน)
3. จัดว่าวิชาไหนสอบช่วงไหน
4. จัดห้องสอบและที่นั่ง แบ่งตามความจุห้อง
5. จัดครูคุมสอบ
6. ใบพิมพ์ — ตารางสอบของนักเรียนรายห้องเรียน · ป้ายติดหน้าห้องสอบ · ใบเวรคุมสอบรายครู
7. สรุปจำนวนคาบคุมสอบต่อครู เพื่อส่งต่อเข้างานอัตรากำลัง

**ไม่ทำในรอบนี้**

- กรอกคะแนนหรือตัดเกรด
- จัดที่นั่งรายคน (เลขที่นั่งต่อนักเรียนรายคน) — จัดแค่ว่าห้องเรียนไหนไปสอบห้องไหน กี่คน
- ตารางสอบซ่อม
- แก้เครื่องจัดตารางเรียนเดิม

**สิ่งที่ถือว่าล้มเหลวแม้โปรแกรมจะทำงานได้**

- ตารางที่ทำให้นักเรียนคนหนึ่งต้องสอบสองวิชาในช่วงเดียวกัน
- ครูคนหนึ่งถูกสั่งให้คุมสองห้องในช่วงเดียวกัน
- ห้องสอบที่นั่งไม่พอกับจำนวนนักเรียนที่ส่งเข้าไป
- ของพวกนี้ต้องเป็นไปไม่ได้ ไม่ใช่เตือนแล้วปล่อยผ่าน

## ข้อจำกัดที่ยกมาจากงานเดิมทั้งหมด

- **ห้ามแตะตารางเรียน** `SLOTS` และ `REQUIREMENTS` อ่านได้อย่างเดียว ตารางสอบเก็บแยกคนละตาราง
- **เครื่องจัดเสนอได้ ไม่เขียนเอง** เหมือนเครื่องจัดตารางเรียน คนกดยอมรับก่อนจึงบันทึก
- **ภาษาไทยทุกข้อความ** รวมข้อความผิดพลาดจากเซิร์ฟเวอร์
- **ไม่เพิ่ม dependency ฝั่งเซิร์ฟเวอร์** Render free tier
- **คำขอเขียนของตารางสอบต้องไม่ไปบวกตัวนับรุ่นของตารางเรียน** ไม่งั้นคนที่กำลังจัดตารางเรียน
  อยู่จะโดนรีโหลดทั้งหน้าทุกครั้งที่มีคนแก้ตารางสอบ — ใช้ทางเดียวกับ `/api/workload/`

## ทางที่เลือก และทางที่ไม่เลือก

**ทาง ก — อยู่ในโปรแกรมจัดตารางเรียน เป็นโหมดใหม่** ✅ เลือกทางนี้

ตารางสอบใช้ทะเบียนครู ห้อง ชั้นเรียน และแผนการสอน ชุดเดียวกับตารางเรียนทั้งหมด อยู่ด้วยกัน
จึงไม่ต้องซิงก์อะไรเลย และคนที่จัดตารางสอบคือคนกลุ่มเดียวกับที่จัดตารางเรียน

**ทาง ข — เว็บแยกเหมือนเว็บลงอัตรากำลัง** ❌

เว็บลงอัตรากำลังแยกออกไปเพราะผู้ใช้คนละกลุ่ม (หัวหน้ากลุ่มสาระ 11 คนกรอกข้อมูลของตัวเอง)
ตารางสอบไม่ใช่แบบนั้น คนทำคืองานวิชาการคนเดิม การแยกจะได้แต่ภาระซิงก์ข้อมูลโดยไม่ได้อะไรคืน

**ทาง ค — ทำเป็นแค่ใบพิมพ์ ไม่มีเครื่องจัด** ❌

ให้คนกรอกเองว่าวิชาไหนสอบช่วงไหนห้องไหนใครคุม แล้วโปรแกรมแค่พิมพ์ให้สวย — เร็วกว่ามาก
แต่ไม่ตรงกับคำว่า "สมบูรณ์" และงานที่หนักจริงคือการเลี่ยงไม่ให้ชนกัน ซึ่งทางนี้ไม่ช่วยเลย
**ถ้าที่จริงต้องการแค่นี้ บอกได้ จะเล็กลงมาก**

## แบ่งเป็นสามขั้น

งานนี้ใหญ่เกินกว่าจะเป็นแผนเดียว แต่ละขั้นใช้งานได้จริงด้วยตัวเอง

### ขั้นที่ 1 — ช่วงสอบ วิชาที่สอบ และตารางสอบ

ตั้งวันสอบและช่วงสอบ · เลือกวิชาที่ต้องสอบจากแผนการสอน · จัดว่าวิชาไหนสอบช่วงไหน
พร้อมด่านกันชน (ทั้งระดับชั้นสอบวิชาเดียวกันพร้อมกัน) · ใบพิมพ์ตารางสอบรายห้องเรียน

จบขั้นนี้ โรงเรียนได้ตารางสอบติดประกาศแล้ว

### ขั้นที่ 2 — ห้องสอบและที่นั่ง

แบ่งห้องเรียนลงห้องสอบตามความจุ · ป้ายติดหน้าห้องสอบ · ตารางสอบที่มีเลขห้องสอบ

### ขั้นที่ 3 — ครูคุมสอบ

จัดเวรคุมสอบ · เลี่ยงครูผู้สอนวิชานั้น · เกลี่ยจำนวนเวรให้ใกล้เคียงกัน · ใบเวรรายครู ·
สรุปจำนวนคาบคุมสอบต่อครูส่งเข้างานอัตรากำลัง

---

## เรื่องที่ต้องตัดสินก่อนเขียนแผนขั้นที่ 1

ผมใส่คำตอบที่คิดว่าใช่ไว้แล้ว ผิดตรงไหนบอกได้

1. **หนึ่งระดับชั้นสอบวิชาเดียวกันพร้อมกันทั้งระดับ** — ม.1 ทุกห้องสอบภาษาไทยช่วงเดียวกัน
   นี่คือวิธีปกติของโรงเรียนไทย และทำให้ข้อห้าม "นักเรียนสอบซ้อน" หายไปเองโดยไม่ต้องไล่รายคน
2. **วิชาที่สอบ ตั้งต้นจากแผนการสอน แล้วให้ติ๊กออกได้** วิชาอย่างลูกเสือหรือชุมนุมไม่มีสอบ
   แต่โปรแกรมไม่ควรเดาเอง ควรเสนอมาทั้งหมดแล้วให้คนตัด
3. **เก็บแยกตามปีและภาคเรียน** เหมือนชั้นเทอมที่ทำไว้ เปิดดูตารางสอบของเทอมก่อนได้
4. **ตารางสอบไม่ผูกกับคาบเรียนปกติ** ช่วงสอบมีเวลาของตัวเอง ไม่ใช่คาบที่ 1–9

## ของที่ค้างอยู่ และกระทบงานนี้โดยตรง

**เว็บลงอัตรากำลังเสร็จแล้วแต่ยังไม่ได้ขึ้นเว็บ** งาน 53 คอมมิตบนสาขาของ Claude Code
ไม่เคยถูก merge เข้า main ตอนนี้บน gh-pages มีแต่โปรแกรมจัดตารางตัวเดียว ไม่มีโฟลเดอร์
`workload/` เลย แปลว่าเว็บที่สั่งทำไปยังไม่มีใครเปิดใช้ได้ รวมถึงตารางรหัสเข้าที่สั่งมาอีกครั้ง

**และการขึ้นเว็บนั้นมีลำดับที่ต้องทำให้ถูก** งานก้อนนั้นแก้ `mock_api.py` ด้วย (เพิ่มตาราง
เพิ่ม route เพิ่มด่านกันตัวนับรุ่น) ซึ่งอยู่บน Render คนละที่กับหน้าเว็บ ถ้า merge แล้วหน้าเว็บ
ขึ้นก่อนที่เซิร์ฟเวอร์จะถูกสั่งให้เอาโค้ดใหม่ไปใช้ เว็บลงอัตรากำลังจะเปิดได้แต่เรียกอะไรไม่ได้เลย
**ต้องอัปเดตเซิร์ฟเวอร์ก่อน แล้วค่อย merge** ซึ่งผู้ใช้เป็นคนสั่งเอง ผมสั่งแทนไม่ได้

ตารางสอบขั้นที่ 3 จะส่งจำนวนคาบคุมสอบเข้างานอัตรากำลัง ถ้าเว็บนั้นยังไม่ขึ้น ขั้นที่ 3
ก็ส่งไปไม่ถึงไหน — ขั้นที่ 1 กับ 2 ไม่กระทบ ทำไปก่อนได้
