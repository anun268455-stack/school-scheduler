# เว็บลงอัตรากำลัง — สเปกการออกแบบ

วันที่ 6 พฤศจิกายน 2569 · สถานะ: รอการยืนยันจากผู้ใช้ · ยังไม่เริ่มเขียนโปรแกรม

---

## 1. ปัญหาที่แก้

ทุกเทอมต้องลอกอัตรากำลังด้วยมือสองรอบ — รอบหนึ่งลงในไฟล์ Excel 39 ชีต
(ชีต `(รายวิชา)` และ `(ครูผู้สอน)` ของแต่ละกลุ่มสาระ รวม 1,463 แถว) และอีกรอบลงในโปรแกรมจัดตารางสอน
ชีต `(ครูผู้สอน)` เองก็เป็นข้อมูลชุดเดียวกันมองจากฝั่งครู ซึ่งก็ลอกด้วยมืออีกต่อหนึ่ง

**เป้าหมาย:** กรอกครั้งเดียว แล้วส่งตรงเข้าโปรแกรมจัดตารางสอนได้

**ไม่ใช่เป้าหมาย:** จัดคาบแทนคน · แก้คาบที่ลงในตารางให้เอง · แทนที่โปรแกรมจัดตารางสอน

พร้อมกันนั้นโปรแกรมจัดตารางสอนจะได้ **ปุ่มสร้างเทอมใหม่** ที่รับอัตรากำลังที่ตรวจผ่านแล้วมาทั้งก้อน
และเก็บทุกเทอมไว้เป็นไฟล์ในระบบ เปิดดูและปริ้นย้อนหลังได้ทุกเทอม (ส่วนที่ 8)

## 2. สถาปัตยกรรม

เว็บใหม่เป็นหน้าเว็บของตัวเองที่ repo แยก ได้ลิงก์คนละชุดจากเว็บตารางเรียน
แต่คุยกับ **เซิร์ฟเวอร์และฐานข้อมูลเดียวกัน**

```
เว็บลงอัตรากำลัง  ──┐
(repo ใหม่, ลิงก์ใหม่)│
                     ├──→  เซิร์ฟเวอร์ Render เดิม  ──→  ฐานข้อมูลเดิม
เว็บตารางเรียน    ──┘        (mock_api.py)
(repo เดิม, ลิงก์เดิม)
```

**ทำไมใช้เซิร์ฟเวอร์เดียวกัน** — การส่งเข้าโปรแกรมจึงเป็นการทำงานภายในฐานข้อมูลเดียวกัน
อ้างครูด้วยรหัสครู ไม่ใช่ชื่อ จึงไม่มีการจับคู่ชื่อเลย
(ชื่อครูในไฟล์ Excel บางชื่อตกตัวการันต์ เช่น "ชนะพันธ" ที่หายไป ์ — ถ้าจับคู่ด้วยชื่อจะเกิดครูซ้ำหรือจับผิดแน่นอน)

**งานตั้งค่าที่เกิดจากการแยก repo** (ครั้งเดียว)

1. ตั้งที่อยู่เซิร์ฟเวอร์ใน repo ใหม่ (`VITE_API_URL` เป็น repo secret เหมือน repo เดิม)
2. เพิ่มที่อยู่เว็บใหม่เข้ารายการต้นทางที่เซิร์ฟเวอร์ยอมรับ (CORS) ไม่งั้นเบราว์เซอร์จะบล็อกทุกคำขอ
3. workflow deploy ของ repo ใหม่ (คัดลอกจาก repo เดิมได้)

## 3. ใครล็อกอิน และเห็นอะไร

### admin (รหัสเดียว)

- เห็นทุกกลุ่มสาระ
- **หน้าที่หลัก: สร้างแถววิชาให้ทุกกลุ่มสาระ** — รหัสวิชา ชื่อวิชา ชั้น ห้องเรียน คาบ/สัปดาห์ หน่วยกิต ประเภทวิชา
- เปิด/ปิดรอบ · ตรวจผ่าน · ตีกลับให้แก้ · ส่งเข้าโปรแกรม
- ตั้ง/เปลี่ยน/ปิด รหัสเข้าของทุกกลุ่มสาระ

### หัวหน้ากลุ่มสาระ (กลุ่มสาระละหนึ่งรหัส, 11 กลุ่ม)

- เห็นแค่แถวของกลุ่มตัวเอง
- **หน้าที่หลัก: ใส่ชื่อครูในแต่ละวิชา** — ครูผู้สอน · ครูสอนร่วม · ห้องปฏิบัติการ · คาบคู่ · หมายเหตุ
- แก้ช่องของแถววิชา (รหัส ชื่อ คาบ ชั้น ห้อง) **ไม่ได้** — ถ้าผิดต้องแจ้ง admin
- กดส่งกลุ่มตัวเองเมื่อครบ
- ดูสรุปจำนวนคาบรายครูของกลุ่มตัวเอง

### รหัสเข้า

- ไม่มีชื่อผู้ใช้ มีแต่รหัส — หน้าแรกคือช่องกรอกรหัสช่องเดียว ระบบรู้เองว่าเป็น admin หรือกลุ่มไหน
- เก็บแบบแฮช อ่านย้อนกลับไม่ได้ ไม่มีฟังก์ชัน "ขอดูรหัส" — ลืมแล้ว admin ตั้งใหม่
- admin ปิดรหัสของกลุ่มได้เมื่อเปลี่ยนหัวหน้ากลุ่มสาระ
- ปุ่ม **ส่งเข้าโปรแกรม** ต้องกรอกรหัส admin ซ้ำอีกครั้งตอนกด เพราะเป็นงานเดียวที่แตะข้อมูลจริงของโปรแกรมจัดตาราง

> **ข้อควรระวังที่แจ้งผู้ใช้แล้ว:** โปรแกรมจัดตารางสอนทุกวันนี้ยังไม่มีระบบล็อกอินเลย
> รหัสบนเว็บใหม่จึงป้องกันได้แค่เว็บใหม่ ใครที่รู้ลิงก์เว็บตารางเรียนยังเข้าไปแก้ตารางได้เหมือนเดิม
> การใส่ล็อกอินให้โปรแกรมจัดตารางเป็นงานแยก ยังไม่อยู่ในสเปกนี้

## 4. ข้อมูลที่เก็บ

### หลักการข้อเดียว

> **อัตรากำลังที่กรอก ต้องเป็นคนละก้อนกับแผนที่ตารางใช้อยู่**

ถ้าเว็บใหม่เขียนทับแผนการสอนเดิมโดยตรง ตารางที่จัดเสร็จแล้วจะถูกกระทบทันทีที่ใครกดบันทึก
เก็บแยกแล้วค่อยเทียบกัน ทำให้ "บอกว่าอะไรเปลี่ยน แล้วเลือกทีละข้อ" เป็นไปได้จริง
และทำให้ย้อนดูได้ว่าเทอมที่แล้วใครสอนอะไร

### ของใหม่ที่เก็บเพิ่ม (อยู่ในฐานข้อมูลเดิม จึงติดไปกับไฟล์สำรองเดิมอัตโนมัติ)

**รอบอัตรากำลัง** — หนึ่งรอบ = หนึ่งภาคเรียน

| สถานะรอบ | กำลังกรอก / ปิดรอบ / ส่งเข้าโปรแกรมแล้ว | ระบบ |
| วันที่เปิด · วันที่ปิด | บันทึกให้ | ระบบ |

### ของเดิมที่ยืมมาใช้ ไม่คัดลอก (อ่านอย่างเดียว)

| ทะเบียนกลุ่มสาระ | แบ่งสิทธิ์รหัสเข้า และแบ่งว่าแถวไหนของกลุ่มใคร |

ถ้ายังไม่มีครู/ห้อง/กลุ่มสาระที่ต้องการ: admin เพิ่มในโปรแกรมจัดตารางสอนก่อน แล้วขึ้นในเว็บใหม่ทันที

### วิชาที่ยังไม่มีในทะเบียน

admin พิมพ์รหัส/ชื่อได้เลย ระบบติดธง "ยังไม่ผูกกับวิชาในระบบ"
แล้วไปถามตอนส่งเข้าโปรแกรมว่าจะสร้างวิชาใหม่ไหม — การกรอกไม่ต้องรอทะเบียน

### วิชาเสรี

คาบเสรีเป็นคนละรูปร่างกับแถววิชาปกติ เพราะหนึ่งคาบมีหลายตัวเลือกให้นักเรียนเลือก
และแต่ละตัวเลือกมีครูของตัวเอง จึงเก็บเป็นสองชั้น: **ชุดคาบเสรี** และ **ตัวเลือกในชุด**

**ชุดคาบเสรี** — admin สร้าง หนึ่งชุด = หนึ่งคาบเสรี

| ช่อง | ตัวอย่าง | ใครกรอก |
|---|---|---|
| ชื่อชุด | คาบเสรี ม.4 ภาคเรียน 1 | admin |
| ห้องที่ใช้ชุดนี้ | ม.4/1 – ม.4/8 (เลือกหลายห้องได้) | admin |
| คาบ/สัปดาห์ | 2 | admin |
| ภาคเรียนที่ | 1 | admin |

**ตัวเลือกในชุด** — admin กำหนดว่ามีตัวเลือกอะไร เพิ่ม/ลบ/แก้ได้

| ช่อง | ตัวอย่าง | ใครกรอก |
|---|---|---|
| รหัสวิชา · ชื่อวิชา | ศ20201 · ดนตรีไทย | admin |
| กลุ่มสาระที่รับผิดชอบตัวเลือกนี้ | ศิลปะ | admin |
| ครูผู้สอน | เลือกจากทะเบียนครู | หัวหน้ากลุ่มสาระที่รับผิดชอบ |
| ห้องที่ใช้สอน | เลือกจากทะเบียนห้อง | หัวหน้ากลุ่มสาระที่รับผิดชอบ |
| หมายเหตุ | | หัวหน้ากลุ่มสาระที่รับผิดชอบ |

กฎที่ตามมา

- **หนึ่งตัวเลือก = หนึ่งแถวในอัตรากำลัง** เพราะครูคนนั้นสอนจริงและต้องได้คาบนับเข้าภาระงาน
- **ตัวเลือกข้ามกลุ่มสาระได้** — ชุดคาบเสรี ม.4 มีได้ทั้งดนตรี คอมพิวเตอร์ เกษตร
  แต่ละตัวเลือกไปโผล่ในหน้าของกลุ่มสาระที่ admin ระบุว่ารับผิดชอบ
- หัวหน้ากลุ่มสาระเห็นแค่ตัวเลือกของกลุ่มตัวเอง ไม่เห็นตัวเลือกอื่นในชุดเดียวกัน
- ชุดจะส่งเข้าโปรแกรมได้ต้องมีครูครบทุกตัวเลือก — ถ้าขาด ระบบบอกว่าขาดตัวเลือกไหนของกลุ่มไหน
- ตอนส่งเข้าโปรแกรม ระบบสร้างคาบเสรีให้ครบทุกห้องที่เลือกไว้ พร้อมตัวเลือกครบทุกตัว
  ตรงตามวิธีที่โปรแกรมเก็บคาบเสรีอยู่แล้ว (คาบเสรีหนึ่งคาบต่อหนึ่งห้อง แต่ละคาบมีรายการตัวเลือกของตัวเอง)
- **การนับคาบ** ครูที่สอนตัวเลือกหนึ่งตัวได้นับคาบเท่ากับ คาบ/สัปดาห์ ของชุด
  ไม่คูณจำนวนห้อง เพราะทุกห้องเรียนคาบเสรีพร้อมกันในคาบเดียว

> **ข้อสมมติที่ต้องยืนยัน:** ทุกห้องในชุดเดียวกันได้ตัวเลือกชุดเดียวกัน
> ถ้าบางห้องมีตัวเลือกไม่เหมือนห้องอื่น ต้องแยกเป็นสองชุด

## 5. การเสนอแถวจากหลักสูตร

ตอน admin เปิดรอบใหม่ ระบบไล่หลักสูตรของทุกห้องแล้วเสนอแถวให้ครบ
พร้อมคาบ/สัปดาห์และกลุ่มสาระที่หลักสูตรระบุไว้

admin เลือกได้ว่าจะ รับทั้งหมด · แก้คาบ · เพิ่มวิชาที่หลักสูตรไม่มี · ลบแถวที่เทอมนี้ไม่เปิด

**เสนอให้ดูก่อน ยังไม่สร้างอะไรจนกดยืนยัน** — แบบเดียวกับปุ่มสร้างหลักสูตรอัตโนมัติที่มีอยู่แล้ว

## 6. งานเดินจากขั้นไหนไปขั้นไหน

แต่ละกลุ่มสาระเดินของตัวเอง ไม่ต้องรอให้ครบทุกกลุ่มจึงตรวจได้

| ขั้น | สถานะ | ใครทำ | แก้แถวได้แค่ไหน | ขั้นถัดไป |
|---|---|---|---|---|
| 1 | เปิดรอบ + ระบบเสนอแถว | admin | ยังไม่สร้างจนกดยืนยัน | ตรวจแถวที่เสนอ |
| 2 | กำลังกรอกแถววิชา | admin | แก้/เพิ่ม/ลบ ได้ทุกกลุ่ม | เปิดให้กลุ่มสาระกรอก |
| 3 | กำลังกรอกชื่อครู | หัวหน้ากลุ่มสาระ | แก้ได้แค่ช่องครู/ห้องปฏิบัติการ/คาบคู่/หมายเหตุ ของกลุ่มตัวเอง | กดส่ง |
| 4 | ส่งแล้ว | หัวหน้ากลุ่มสาระ | ล็อก (ขอ admin ปลดล็อกได้) | admin ตรวจ |
| 5 | ตีกลับให้แก้ | admin | กลุ่มสาระแก้ได้อีก พร้อมหมายเหตุ | กลับขั้น 3 |

| 7 | ส่งเข้าโปรแกรมแล้ว | admin | ล็อกถาวร เก็บเป็นประวัติ | จบรอบ |

## 7. การส่งเข้าโปรแกรมจัดตารางสอน

มีสองทางเข้า และต่างกันชัดเจน

| ทางเข้า | ใช้เมื่อ | วิธี |
|---|---|---|
| **สร้างเทอมใหม่** | ขึ้นเทอมใหม่ ตารางยังไม่ได้จัด | รับทั้งก้อน ไม่ต้องเทียบ — ดูส่วนที่ 8 |
| **อัปเดตกลางเทอม** | ตารางใช้งานอยู่ แต่อัตรากำลังเปลี่ยน | เทียบทีละข้อ — ส่วนนี้ |

### กฎเหล็ก

> **การอัปเดตกลางเทอมเขียนแค่แผนการสอน ไม่แตะคาบที่ลงในตารางแล้วแม้แต่คาบเดียว**

ข้อนี้ผู้ใช้ยืนยันเอง และตรงกับข้อกำหนดเดิมของโปรแกรมที่ว่าเครื่องจัดตารางเสนอได้แต่ไม่เขียนคาบเอง

### อัปเดตกลางเทอม (ตารางจัดไปแล้ว แต่อัตรากำลังเปลี่ยน)

ระบบไม่เขียนอะไรจนกดยอมรับ แต่แสดงหน้าเทียบก่อน แยกเป็น 4 กอง

| กอง | หมายถึง | กระทบคาบที่ลงแล้วไหม | กดให้แก้แล้วเกิดอะไร |
|---|---|---|---|
| **แถวใหม่** | วิชาที่รอบก่อนไม่มี | ไม่กระทบ | เพิ่มแผนใหม่ คาบยังไม่ลง |
| **คาบเปลี่ยนจำนวน** | เช่น 3 → 4 คาบ/สัปดาห์ | กระทบ | แก้จำนวนคาบในแผน · คาบที่ลงแล้วคงเดิมทั้งหมด |
| **เปลี่ยนครู** | ครูคนเดิมออก คนใหม่เข้า | กระทบ | แก้ชื่อครูในแผน · คาบที่ลงแล้วยังเป็นครูคนเดิม |
| **แถวที่หายไป** | เทอมนี้ไม่เปิดแล้ว | กระทบ | ลบแผน · คาบที่ลงแล้วคงอยู่ ติดป้าย "เกินแผน" |

แต่ละข้อมีปุ่ม **ให้แก้** / **ไม่แก้** ของตัวเอง กดแค่ข้อที่ต้องการ ที่ไม่กดก็คงเดิมไว้

**คาบที่ไม่มีแผนรองรับ** — เมื่อลบแผนแล้วคาบยังอยู่ โปรแกรมจัดตารางจะขึ้นป้าย "เกินแผน" ที่คาบนั้น
ไม่ลบให้ และไม่ถือเป็นข้อผิดพลาดที่ขัดการบันทึก — คนเป็นผู้ตัดสินใจว่าจะลบหรือเก็บไว้

**คาบเสรี** เข้ากองเดียวกับข้ออื่น แต่แยกย่อยได้สามแบบ: ตัวเลือกใหม่ในชุดเดิม · เปลี่ยนครูของตัวเลือก ·
ตัวเลือกที่ถูกเอาออก กดให้แก้แล้วแก้แค่รายการตัวเลือกของคาบเสรีที่มีอยู่ ไม่ย้ายและไม่ลบตัวคาบเสรีเอง
และไม่แตะห้องที่ตัวเลือกนั้นถูกจองไว้แล้ว

### รายการงานที่ต้องไปทำเอง

หลังกดส่ง ระบบสร้างรายการว่าต้องไปจัดการคาบอะไร เช่น
"ท21101 ม.1/1 แผนเป็น 4 คาบ ลงไว้ 3 คาบ — ขาด 1 คาบ" หรือ
"ค21101 ม.2/3 เปลี่ยนครูในแผนเป็นครู ข แต่ 3 คาบที่ลงไว้ยังเป็นครู ก"

**รายการนี้ขึ้นในโปรแกรมจัดตารางสอน ไม่ใช่เว็บใหม่** เพราะที่นั่นคือที่ที่ไปแก้คาบ

### ประวัติ

เก็บว่าใครกดส่งเข้าโปรแกรมเมื่อไหร่ และข้อไหนถูกยอมรับ/ปฏิเสธ เพื่อย้อนดูได้ว่าแผนเปลี่ยนเพราะอะไร

## 8. ปุ่มสร้างเทอมใหม่ และไฟล์เทอม

### เทอมคือก้อนข้อมูลหนึ่งก้อน

หนึ่งเทอม = หนึ่งไฟล์ในระบบ เก็บทุกอย่างของเทอมนั้นไว้ครบ —
ตารางคาบทั้งหมด · แผนการสอน · หลักสูตร · อัตรากำลังรอบที่ใช้ · การตั้งค่าใบพิมพ์และลายเซ็น

ไฟล์อยู่ในระบบ ไม่ต้องเก็บเอง เปิดดูเทอมไหนก็ได้ตอนไหนก็ได้ และดาวน์โหลดเก็บไว้เองก็ได้

**แก้ได้ทีละเทอมเดียว คือเทอมที่ใช้งานอยู่** เทอมที่ปิดแล้วเปิดดูกับปริ้นได้เท่านั้น

### กด "สร้างเทอมใหม่" แล้วเกิดอะไร

1. เซฟเทอมที่กำลังใช้อยู่ลงไฟล์ของมันให้เรียบร้อยก่อน
2. ถามปีการศึกษาและภาคเรียนของเทอมใหม่
3. ให้เลือกรอบอัตรากำลังที่ "ตรวจผ่าน" แล้วจากเว็บลงอัตรากำลัง
4. แสดงสรุปก่อนลงมือ — จะได้แผนการสอนกี่รายการ · ครูกี่คน · คาบรวมเท่าไหร่ ·
   มีวิชาใหม่ที่ต้องสร้างกี่วิชา · ชุดคาบเสรีกี่ชุด
   พร้อมคำเตือนว่า **กดแล้วเทอมที่ใช้งานอยู่จะถูกปิดและแก้ไม่ได้อีก**
5. กดยืนยัน → ปิดและล็อกเทอมเดิม → สร้างไฟล์เทอมใหม่ ใส่หลักสูตรและแผนการสอนครบ
   **ตารางเริ่มว่าง** แล้วเปิดเทอมใหม่ให้
6. ไปจัดคาบตามปกติ

> **เทอมเก่าไม่ถูกแตะเลย** — ตารางที่จัดไว้ของเทอม 1 ยังอยู่ครบเหมือนเดิมแม้สร้างเทอม 2 แล้ว
> เพียงแต่กลายเป็นอ่านอย่างเดียว

**แถวอัตรากำลังเป็นทั้งหลักสูตรและแผนการสอน** — แถวหนึ่งมี ชั้น · ห้อง · รหัสวิชา · ชื่อวิชา ·
หน่วยกิต · คาบ/สัปดาห์ อยู่แล้ว ซึ่งก็คือรายการหลักสูตรหนึ่งรายการ
ตอนสร้างเทอมใหม่ ระบบจึงเขียนทั้งหลักสูตรและแผนการสอนของเทอมใหม่จากแถวเดียวกัน ไม่ต้องลงหลักสูตรซ้ำ
ส่วนหลักสูตรของเทอมก่อนยังอ่านอย่างเดียว ใช้เสนอแถวให้ตอนเปิดรอบอัตรากำลัง (ส่วนที่ 5)

### หน้ารายการเทอม

| ชื่อเทอม | สถานะ | คาบที่ลงแล้ว | แก้ครั้งสุดท้าย | |
|---|---|---|---|---|
| 1/2569 | **ใช้งานอยู่ · แก้ได้** | 2,735 คาบ | 6 พ.ย. 17:20 | ทำงานต่อ |
| 2/2568 | ปิดแล้ว · อ่านอย่างเดียว | 2,680 คาบ | 28 ต.ค. | เปิดดู · ปริ้น · ดาวน์โหลด |
| 1/2568 | ปิดแล้ว · อ่านอย่างเดียว | 2,702 คาบ | 15 พ.ค. | เปิดดู · ปริ้น · ดาวน์โหลด |

### เทอมเก่าเปิดดูและปริ้นได้ แก้ไม่ได้

เมื่อขึ้นเทอมใหม่ เทอมเก่าถูกปิดและล็อก **เปิดดูกับปริ้นได้ แก้ไม่ได้**
ตารางของเทอมที่ปิดแล้วจึงเป็นหลักฐานที่เชื่อถือได้ ว่าเทอมนั้นจัดไว้แบบไหนจริง ๆ
และไม่มีใครเผลอแก้เทอมเก่าโดยไม่รู้ตัวได้เลย

ในโหมดอ่านอย่างเดียว

- ตารางแสดงครบเหมือนเดิมทุกช่อง ย้ายคาบไม่ได้ ลบไม่ได้ ไม่มีปุ่มบันทึก
- ใบพิมพ์ทุกใบใช้ได้ครบ — ตารางเรียน ตารางครู ตารางห้อง ใบอัตรากำลัง
- ใบพิมพ์ทุกใบมีชื่อเทอมอยู่บนกระดาษ จะได้ไม่แจกตารางผิดเทอม
- มีแถบบอกค้างไว้บนหัวจอว่า "เทอม 2/2568 · ปิดแล้ว ดูและปริ้นได้เท่านั้น"
- เซิร์ฟเวอร์ปฏิเสธคำขอแก้ไขของเทอมที่ปิดแล้วทุกชนิด ไม่ใช่แค่ซ่อนปุ่มบนหน้าจอ
- เปิดดูได้ครั้งละหนึ่งเทอม เทียบสองเทอมพร้อมกันบนจอไม่ได้ ถ้าต้องเทียบให้ปริ้นออกมาเทียบ

**ทางออกกรณีกดผิด** — ถ้าเผลอกดสร้างเทอมใหม่ ต้องมีทางกลับ ไม่งั้นงานทั้งเทอมค้างอยู่ในก้อนที่แก้ไม่ได้
จึงมีปุ่ม **ปลดล็อกเทอม** ที่ admin เท่านั้นกดได้ ต้องพิมพ์ชื่อเทอมยืนยัน
และระบบบันทึกไว้ว่าใครปลดเมื่อไหร่ — มีไว้สำหรับกรณีกดผิด ไม่ใช่วิธีใช้งานปกติ

### สถิติย้อนหลัง

เมื่อทุกเทอมถูกเก็บไว้ครบ ตัวเลขย้อนหลังก็คำนวณได้ฟรี ไม่ต้องกรอกอะไรเพิ่ม

- คาบรวมของแต่ละเทอม และของแต่ละกลุ่มสาระ
- คาบของครูแต่ละคน เทียบกันข้ามเทอมได้ — ใครคาบเพิ่มขึ้น ใครลดลง
- สัดส่วนการใช้ห้อง แต่ละห้องถูกใช้กี่คาบจากที่มีได้
- จำนวนวิชาที่เปิดจริงในแต่ละเทอม

### ผลที่ตามมา: ลบครูหรือห้องที่เทอมเก่าใช้อยู่ไม่ได้

ทะเบียนครู ห้อง วิชา กลุ่มสาระ **ใช้ร่วมกันทุกเทอม** ไม่แยกตามเทอม
ไม่งั้นต้องกรอกครู 150 คนใหม่ทุกเทอม

ผลคือถ้าลบครูที่เทอมเก่ายังมีคาบอยู่ ตารางเทอมเก่าจะพัง — ระบบจึงไม่ให้ลบ
แทนที่จะลบ ให้ทำเครื่องหมาย **"ไม่ปฏิบัติงานแล้ว"** หายจากรายการให้เลือกในเทอมใหม่
แต่ยังแสดงถูกต้องในตารางเทอมเก่า ใช้กับห้องที่เลิกใช้และวิชาที่เลิกเปิดเหมือนกัน

### ขนาด

ไฟล์เทอมคือสำเนาข้อมูลแบบเดียวกับที่เซิร์ฟเวอร์เก็บอยู่แล้ว บีบอัดไว้
ทุกวันนี้เซิร์ฟเวอร์เก็บสำเนาแบบนี้ไว้ 30 ชุดเป็นประวัติอยู่แล้ว เทอม 20 เทอมจึงไม่กินที่มากกว่าที่ใช้อยู่
หน้ารายการเทอมแสดงขนาดจริงของแต่ละเทอม ไม่ต้องเดา

### งานหลังบ้านที่ข้อนี้เพิ่มเข้ามา (แก้ไข 6 พ.ย. หลังอ่านโค้ด)

ตอนแรกประเมินว่าข้อนี้เป็นงานหลังบ้านก้อนใหญ่ที่สุด **อ่านโค้ดแล้วเบากว่าที่คิดมาก**
เพราะของที่ต้องใช้มีอยู่แล้วเกือบครบ

- ฟังก์ชันที่ทำสำเนาข้อมูลทั้งก้อน และฟังก์ชันที่เอาสำเนากลับเข้าระบบ — มีแล้ว ใช้อยู่ทุกวัน
  ตอนเซฟและตอนกู้คืนจากประวัติ
- ตารางเก็บสำเนาในฐานข้อมูลพร้อมวันเวลาและขนาด — มีแล้ว (ประวัติ 30 ชุด) ตารางเทอมเป็นแบบเดียวกัน
  ต่างแค่มีชื่อเทอม ไม่ถูกลบทิ้งตามอายุ และมีสถานะปิด/เปิด
- **จุดที่ทุกคำขอเขียนข้อมูลวิ่งผ่านเหมือนกันหมด มีอยู่แล้วหนึ่งจุด** การ์ดกันเขียนของเทอมที่ปิดแล้ว
  จึงใส่ที่จุดเดียว ไม่ต้องไปแก้ทุก endpoint ทีละตัว

**การเปิดดูเทอมเก่าไม่แตะข้อมูลในเครื่องเซิร์ฟเวอร์เลย** — เซิร์ฟเวอร์ส่งสำเนาของเทอมนั้นมาให้
เบราว์เซอร์ที่ขอ แล้วหน้าจอนั้นแสดงสำเนาและหยุดซิงค์สดไว้ชั่วคราว
คนอื่นที่กำลังจัดตารางเทอมปัจจุบันอยู่จึงไม่รู้สึกอะไรเลย ซึ่งสำคัญมาก
เพราะถ้าการเปิดดูไปเปลี่ยนข้อมูลของเซิร์ฟเวอร์ ทุกคนจะเห็นเทอมเก่าพร้อมกันทันที

## 9. ผลพลอยได้: ชีต (ครูผู้สอน) ไม่ต้องลอกอีก

ชีต `(ครูผู้สอน)` ของไฟล์เดิมเป็นข้อมูลชุดเดียวกันมองจากฝั่งครู พร้อมยอดรวมคาบ
เมื่อข้อมูลอยู่ในระบบแล้ว ระบบคำนวณและรวมคาบให้สด จึงไม่ต้องลอก และไม่หลุดจากกัน

หัวหน้ากลุ่มสาระเห็นของกลุ่มตัวเอง · admin เห็นทุกกลุ่ม

## 10. ของที่ไม่ทำในรอบนี้

- ล็อกอินให้โปรแกรมจัดตารางสอน (งานแยก)
- นำเข้าไฟล์ Excel อัตรากำลังเดิมโดยตรง — ชื่อครูในไฟล์ตกตัวการันต์หลายชื่อ
  การเลือกจากทะเบียนครูเร็วกว่าและไม่ผิด
- จัดคาบแทนคน หรือแก้ตารางให้ตามอัตรากำลัง
- แก้ไขทะเบียนครู/ห้อง/วิชา จากเว็บใหม่ (ทำในโปรแกรมเดิม)
- เปิดสองเทอมพร้อมกันเพื่อเทียบบนจอ
- ยกคาบของเทอมก่อนมาเป็นร่างของเทอมใหม่ (ผู้ใช้เลือกให้เริ่มจากตารางว่าง)
- แก้ตารางของเทอมที่ปิดแล้ว (ผู้ใช้เลือกให้ดูและปริ้นอย่างเดียว) — ยกเว้นปุ่มปลดล็อกกรณีกดผิด

## 11. สิ่งที่ต้องทดสอบก่อนปล่อยใช้

1. รหัสกลุ่มสาระเห็นแถวของกลุ่มอื่นไม่ได้ — ทั้งบนหน้าจอและจากคำขอตรงไปที่เซิร์ฟเวอร์
2. หัวหน้ากลุ่มสาระแก้ช่องของแถววิชา (รหัส ชื่อ คาบ) ไม่ได้ แม้ส่งคำขอตรง
3. ส่งเข้าโปรแกรมแล้ว **จำนวนคาบที่ลงในตารางไม่เปลี่ยนแม้แต่คาบเดียว** ทั้งสามกองที่กระทบ
4. เทียบรอบที่สองตรวจจับได้ครบทั้ง 4 กอง และกด "ไม่แก้" แล้วไม่เขียนอะไรเลยจริง
5. วิชาที่ยังไม่ผูกทะเบียน ส่งเข้าโปรแกรมแล้วสร้างวิชาใหม่ถูกต้อง และไม่สร้างซ้ำถ้ากดสองครั้ง
6. CORS: เว็บใหม่เรียกเซิร์ฟเวอร์ได้ และต้นทางที่ไม่ได้อนุญาตเรียกไม่ได้
7. ยอดรวมคาบรายครูตรงกับชีต `(ครูผู้สอน)` ของไฟล์เดิม อย่างน้อยสองกลุ่มสาระ
8. คาบเสรี: ส่งชุดที่คลุม 8 ห้องแล้วได้คาบเสรีครบ 8 ห้อง ตัวเลือกครบทุกตัว
   และครูที่สอนหนึ่งตัวเลือกได้นับคาบเท่า คาบ/สัปดาห์ ของชุด **ไม่คูณ 8**
9. หัวหน้ากลุ่มสาระเห็นแค่ตัวเลือกคาบเสรีของกลุ่มตัวเอง ไม่เห็นตัวเลือกอื่นในชุดเดียวกัน
10. ตัวเลือกคาบเสรีที่กรอกครูครบ ขึ้นในใบอัตรากำลังของครูคนนั้น (จุดที่เคยพลาดมาแล้วเมื่อ 6 พ.ย.)

ข้อสอบเรื่องเทอม — สำคัญที่สุดเพราะเสี่ยงที่สุด

11. สร้างเทอมใหม่แล้ว **คาบของเทอมเก่าต้องครบเท่าเดิมทุกคาบ** นับก่อนและหลังเทียบกันตรง ๆ
12. เทอมใหม่เริ่มจากตารางว่างจริง (0 คาบ) แต่มีแผนการสอนและหลักสูตรครบ
13. สลับเทอมไปกลับสามรอบแล้วข้อมูลทั้งสองเทอมยังครบ ไม่รั่วข้ามเทอม
13ก. **เปิดดูเทอมเก่าในเบราว์เซอร์หนึ่ง ไม่กระทบอีกเบราว์เซอร์ที่กำลังจัดตารางเทอมปัจจุบัน**
    และซิงค์สดของหน้าที่เปิดดูเทอมเก่าต้องหยุด ไม่ดึงข้อมูลเทอมปัจจุบันมาทับสำเนาที่ดูอยู่
14. เทอมที่ปิดแล้วแก้ไม่ได้จริง — ลากคาบ ลบคาบ กดบันทึก ทำไม่ได้ทั้งบนหน้าจอ
    **และเมื่อส่งคำขอแก้ไขตรงไปที่เซิร์ฟเวอร์** เซิร์ฟเวอร์ต้องปฏิเสธ ไม่ใช่แค่ซ่อนปุ่ม
15. ลบครูที่เทอมเก่ามีคาบอยู่ — ระบบต้องปฏิเสธ และเสนอให้ทำเครื่องหมาย "ไม่ปฏิบัติงานแล้ว" แทน
16. ครูที่ทำเครื่องหมาย "ไม่ปฏิบัติงานแล้ว" ยังแสดงชื่อถูกต้องในตารางเทอมเก่า
17. ใบพิมพ์ของเทอมเก่าครบทุกแบบ (ตารางเรียน ครู ห้อง อัตรากำลัง)
    และมีชื่อเทอมที่เปิดดูอยู่บนกระดาษ ไม่ใช่ชื่อเทอมที่ใช้งานอยู่
18. สร้างเทอมใหม่ขณะที่ยังมีการแก้ที่ไม่ได้เซฟ — ต้องเซฟเทอมเดิมให้ครบก่อนปิด ไม่ทิ้งงาน
19. ปลดล็อกเทอม — ต้องพิมพ์ชื่อเทอมยืนยัน บันทึกประวัติว่าใครปลดเมื่อไหร่
    และคนที่ไม่ใช่ admin กดไม่ได้
20. หน้าสถิติ — ยอดคาบของแต่ละเทอมตรงกับที่นับจากตารางของเทอมนั้นตรง ๆ
