# หลักสูตร (Curriculum) — เอกสารออกแบบ

วันที่ 2026-10-16 · ระบบจัดตารางเรียน

## 1. โจทย์

คำพูดของโรงเรียน:

> "อยากให้มีการนำวิชาต่างๆ เข้าลงไปในหลักสูตร ซึ่งเป็นฐานข้อมูลหลักที่จะเอาไปใช้
> ทั้งเพิ่มวิชาครู หรือแม้แต่ตอนจบเราก็สามารถตรวจสอบดูได้ว่าห้องไหนยังขาดหรือมี
> วิชาไหนเกินออกมา โดยจะกรอกเป็นตารางหลักสูตรแต่ละแผน ซึ่งเราจะสามารถเลือกห้องได้
> ว่าห้องนี้ใช้แผนอันนี้ ห้องนี้ใช้แผนอันนี้ (มีปุ่มก๊อปปี้หลักสูตรไปทำหลักสูตรใหม่
> ได้ด้วย จะได้ไม่ต้องค่อยเพิ่มวิชาใหม่)"

> "หลักสูตรนี้จะเป็นฐานหลักใหญ่ที่สุดในการอ้างอิงวิชาทั้งหมดที่ครูสอน ถ้ามีการ
> สร้างเกินจะมีแจ้งเตือนขึ้นมา"

### ปัญหาที่มันแก้ (วัดจากข้อมูลจริง)

ห้องเรียนมีช่อง "แผน" อยู่แล้ว (วิชาการทั่วไป · วิทย์-คณิต · SMTP · MEP · ไทย-สังคม
· ศิลป์-คำนวณ · ภาษา · EP · อังกฤษ-จีน · วิทย์-กีฬา) แต่ไม่มีอะไรอยู่เบื้องหลังมัน
เลย — เป็นแค่ข้อความ ผลคือห้องที่แผนเดียวกันระดับเดียวกันเรียนวิชาไม่เหมือนกัน
โดยไม่มีอะไรฟ้อง:

| ระดับ + แผน | จำนวนห้อง | ชุดวิชาที่ต่างกัน |
|---|---|---|
| ม.3 วิชาการทั่วไป | 10 | **6 แบบ** |
| ม.4 (ยังไม่ได้ใส่แผน) | 8 | **8 แบบ** |
| ม.2 วิชาการทั่วไป | 8 | 3 แบบ |
| ม.1 วิชาการทั่วไป | 6 | 3 แบบ |

แผนการสอนทั้งหมด 1,220 แถว พิมพ์เข้ามาทีละแถวโดยหลายคนเป็นเวลาหลายสัปดาห์ และ
บางส่วนนำเข้าจากสเปรดชีต ไม่มีจุดไหนในระบบที่ตอบได้ว่า "ห้องนี้ควรเรียนอะไรบ้าง"

### สิ่งที่ถือว่าสำเร็จ

1. โรงเรียนกรอกหลักสูตรแต่ละแผนได้ แล้วชี้ว่าห้องไหนใช้แผนไหน
2. ผูกห้องเข้ากับหลักสูตรแล้ว ระบบ**เสนอ**ให้ว่าจะสร้าง/แก้/เอาวิชาไหนออก และ
   ไม่ลงมือจนกว่าจะกดยืนยัน
3. เพิ่มวิชาที่ไม่มีในหลักสูตรของห้องนั้น → **ถูกปฏิเสธ**
4. หน้าเดียวตอบได้ว่าทั้งโรงเรียนห้องไหนขาด/เกิน/คาบไม่ตรง
5. ข้อมูล 1,220 แถวที่มีอยู่แล้วไม่พังระหว่างทาง และเปิดใช้ทีละชั้นได้

### สิ่งที่คำตอบของโรงเรียนกำหนดไว้แล้ว

| คำถาม | คำตอบ |
|---|---|
| ผูกห้องแล้วทำอะไรกับวิชาของห้อง | สร้างให้ **แต่ถามก่อนทุกครั้ง** |
| ห้องย่อย (ม.4/6ก ข ค) อยู่ตรงไหน | **ห้องย่อยเลือกหลักสูตรของตัวเองได้** |
| เพิ่มวิชานอกหลักสูตร | **ห้ามเลย ต้องไปแก้หลักสูตรก่อน** |

### ข้อสมมติ (แจ้งไว้แล้ว ยังไม่ถูกทักท้วง)

- หลักสูตรหนึ่งชุด = **หนึ่งภาคเรียน** ทั้งแอปจัดตารางทีละภาคอยู่แล้ว และไม่มี
  แนวคิดภาคเรียนในระบบเลย
- หลักสูตรนับเฉพาะ**วิชาปกติ** คาบเสรี · ชุมนุม · กิจกรรม มีระบบของตัวเองอยู่แล้ว
  และไม่อยู่ในหลักสูตร แต่หน้าตรวจจะนับคาบรวมให้เห็นว่าทั้งสัปดาห์เต็มไหม

## 2. ทางเลือกที่พิจารณา

**ก. หลักสูตรเป็นข้อมูลของตัวเอง ผูกกับห้อง + บังคับตอนเขียน** ← เลือกอันนี้

**ข. หลักสูตรเป็นแค่เทมเพลต** สร้างวิชาให้ได้ แต่ไม่ห้ามอะไร — ตกไป โรงเรียนระบุ
ชัดว่าต้องห้าม

**ค. ใช้ "ห้องต้นแบบ" แทนตัวหลักสูตร** ชี้ไปที่ ม.4/1 แล้วห้องอื่นต้องเหมือน —
พิมพ์น้อยกว่า แต่เขียนหลักสูตรที่ยังไม่มีห้องไหนใช้ไม่ได้ และพอแก้ห้องต้นแบบ
ห้องอื่นพังตามทั้งหมด ตกไป

## 3. ตัวข้อมูล

### 3.1 หลักสูตร

```python
{
  "id": 1,
  "name": "ม.4 วิทย์-คณิต",
  "note": "",                       # ว่างได้
  "rows": [
      {"subject_id": 12, "weekly_count": 3},
      {"subject_id": 40, "weekly_count": 2},
  ],
}
```

แถวมีแค่ **วิชา + จำนวนคาบ/สัปดาห์** เท่านั้น คาบคู่ · ห้องประจำวิชา · หน่วยกิต ·
กลุ่มสาระ อยู่ที่ตัววิชาอยู่แล้ว การคัดลอกมาไว้ในหลักสูตรด้วยจะสร้างคำตอบที่สอง
ให้กับคำถามเดียว ซึ่งเป็นที่มาของบั๊กทั้งหมดที่ไล่แก้มาในสัปดาห์นี้

**วิชาซ้ำในหลักสูตรเดียวกันไม่ได้** — หนึ่งวิชาหนึ่งแถว ถ้าต้องการสองครูสอน
วิชาเดียวกันให้ห้องเดียว นั่นคือ "สอนร่วม" ซึ่งอยู่ที่แผนการสอน ไม่ใช่หลักสูตร

### 3.2 การผูกห้อง

เพิ่มช่อง `curriculum_id` ที่ตัวห้องเรียน (`GROUPS`) — ห้องแม่หรือห้องย่อยก็ได้
ไม่มีการสืบทอดจากห้องแม่: ม.4/6ก ที่ไม่ได้ผูกอะไรไว้ คือห้องที่ยังไม่ผูก ไม่ใช่
ห้องที่ใช้หลักสูตรของ ม.4/6 การสืบทอดเงียบๆ จะทำให้ "ทำไมห้องนี้ถูกห้าม" ตอบยาก

ช่อง `plan` เดิมยังอยู่เป็นป้ายชื่อ ไม่ถูกแตะและไม่ถูกใช้ตัดสินอะไร

**`curriculum_id` เป็น `None` = ไม่ถูกบังคับอะไรเลย** นี่คือวาล์วนิรภัยของทั้ง
ระบบ ทำให้เปิดใช้ทีละชั้นได้ และทำให้ข้อมูล 1,220 แถวที่มีอยู่ยังแก้ไขได้ตามปกติ
ระหว่างที่โรงเรียนยังกรอกหลักสูตรไม่เสร็จ

### 3.3 ที่เก็บ

`CURRICULA` เป็นลิสต์ระดับโมดูล ต่อสายเข้ากับที่เดิมทั้งสี่จุดใน `mock_api.py`:

- `_SAVE_KEYS` — เพิ่ม `"curricula"`
- `_snapshot()` — เพิ่มคีย์
- `_restore()` — เพิ่มคู่ `("curricula", CURRICULA)`
- ตัวนับ id — เพิ่มคู่ `("curriculum", CURRICULA)`

ลืมจุดใดจุดหนึ่งแปลว่าหลักสูตรหายตอนเซิร์ฟเวอร์รีสตาร์ต หรือสำรองข้อมูลแล้วกู้คืน
กลับมาไม่ครบ ทั้งสี่จุดมีเทสต์คุม

## 4. โค้ดอยู่ที่ไหน

`mock_api.py` ตอนนี้ 8,800 บรรทัด การเพิ่มระบบย่อยใหม่ลงไปอีกทำให้แย่ลง — ตรรกะ
หลักสูตรจึงอยู่ใน **`curriculum.py`** ไฟล์ของตัวเอง ตามแบบที่ `substitution.py`
ทำอยู่แล้วในโปรเจกต์นี้ (ผูกเข้าด้วย `bind(**tables)`)

`curriculum.py` รับผิดชอบ:

- `plan_for(group_id)` — หลักสูตรของห้องนี้ หรือ `None`
- `diff(group_id)` — เทียบหลักสูตรกับแผนการสอนจริงของห้อง → รายการ ขาด/เกิน/คาบไม่ตรง
- `check_row(group_id, subject_id, weekly_count)` — ผ่านหรือไม่ผ่าน พร้อมเหตุผล
- `audit()` — ทั้งโรงเรียน ห้องละบรรทัด

`mock_api.py` เก็บไว้แค่ endpoint บางๆ กับการต่อสายเรื่องบันทึกข้อมูล

## 5. สิ่งที่ทำได้

### 5.1 กรอกหลักสูตร

เพิ่ม/ลบ/แก้แถว (วิชา + คาบ/สัปดาห์) ลบหลักสูตรที่ยังมีห้องผูกอยู่ → ปฏิเสธ พร้อม
บอกว่ามีห้องไหนผูกอยู่บ้าง (ปลดห้องก่อนถึงลบได้)

### 5.2 ก๊อปปี้หลักสูตร

`POST /api/curricula/{id}/copy` → ชุดใหม่ วิชาครบ ชื่อ "<เดิม> (สำเนา)" ไม่มีห้อง
ผูกอยู่ แก้ต่อได้ทันที

### 5.3 ผูกห้อง

เลือกหลายห้องพร้อมกันแล้วผูกเข้าหลักสูตรเดียว · ปลดห้องออกได้ · การผูกไม่ไปแตะ
วิชาของห้องเลย มันแค่ทำให้หน้าเทียบและการบังคับเริ่มทำงาน

### 5.4 เทียบและปรับห้องให้ตรง

หัวใจของฟีเจอร์ กดแล้วได้ตารางเทียบก่อนเสมอ:

| | วิชา | ในหลักสูตร | ห้องนี้มี | จะทำ |
|---|---|---|---|---|
| ➕ | ว31101 | 3 คาบ | – | สร้างแถวใหม่ (ครูเว้นว่าง) |
| ✏️ | ค31102 | 4 คาบ | 3 คาบ | แก้เป็น 4 |
| ➖ | ศ30246 | – | 2 คาบ | เอาออก |

ติ๊กได้ทีละบรรทัดหรือรับทั้งหมด **ไม่กดยืนยันไม่มีอะไรเปลี่ยน**

กฎที่ต้องระวังตอนลงมือ:

- แถวที่สร้างใหม่ **เว้นครูไว้ (`teacher_id = 0`)** ระบบเดิมถือว่าแถวไม่มีครูคือ
  แถวที่ยังไม่พร้อมจัด จะถูกรายงานว่า "ยังไม่ได้เลือกครู" ไม่ถูกจัดลงตาราง —
  ตรงกับความจริงพอดี
- **เอาออก** ลบเฉพาะแถวในแผนการสอน **ไม่แตะคาบที่ลงตารางไว้แล้ว** ถ้ามีคาบของ
  วิชานั้นอยู่ในตาราง ให้เตือนว่าจะกลายเป็นคาบที่ไม่มีแผนรองรับ และให้โรงเรียน
  ตัดสินใจเอง (ตรงกับแนวเดิมของแอป: ไม่ลบงานของคนอื่นเงียบๆ)
- แถวที่อยู่ใน**เซ็ตห้องย่อย** (`parallel_group_key`) หรือเป็น**สอนร่วม** ไม่ถูก
  เสนอให้ลบอัตโนมัติ — ขึ้นเป็นคำเตือนแทน เพราะการลบข้างเดียวทำให้เซ็ตพัง
- วิชาที่ **"อยู่ในคาบเสรีแล้ว"** (`served_by_elective`) ไม่นับว่าเกิน

### 5.5 สร้างหลักสูตรจากห้องที่มีอยู่

`POST /api/curricula/from-group/{group_id}` → หลักสูตรใหม่ที่มีวิชาของห้องนั้นครบ
ทางขึ้นสำหรับข้อมูล 1,220 แถวที่มีอยู่ ชี้ไปที่ ม.4/1 ได้หลักสูตรทันที แล้วผูก
ห้องที่เหลือ หน้าเทียบจะโชว์ที่เพี้ยนออกมาเอง

### 5.6 ตรวจทั้งโรงเรียน

`GET /api/curricula/audit` — ห้องละบรรทัด: หลักสูตรที่ผูกไว้ · ขาดกี่วิชา · เกิน
กี่วิชา · คาบไม่ตรงกี่วิชา · คาบรวม/สัปดาห์ หน้าตาเหมือนหน้า "ตรวจคาบสุดท้าย /
คาบว่าง" ที่มีอยู่แล้ว กรองเฉพาะห้องที่ไม่ตรงได้

## 6. การบังคับ

เปิดเมื่อห้องนั้นผูกหลักสูตรไว้เท่านั้น ปฏิเสธเมื่อ:

1. วิชานั้น**ไม่มีในหลักสูตร**ของห้องนั้น
2. `weekly_count` **เกิน**ที่หลักสูตรกำหนด (น้อยกว่าได้ ถือว่ากรอกยังไม่ครบ)

ข้อความต้องบอกว่าติดหลักสูตรชุดไหนและหลักสูตรว่าอย่างไร เช่น

> เพิ่ม ว31101 ให้ ม.4/1 ไม่ได้ — หลักสูตร "ม.4 วิทย์-คณิต" ไม่มีวิชานี้
> (แก้หลักสูตรก่อน แล้วค่อยเพิ่ม)

### จุดที่ต้องบังคับ

| ทาง | หมายเหตุ |
|---|---|
| `POST /api/timetable/requirements` | เพิ่มทีละแถวจากหน้าจอ |
| `PUT /api/timetable/requirements/{id}` | แก้วิชา/คาบ/ห้อง — เช็ก**ค่าหลังแก้** และเทียบกับหลักสูตรของ**ห้องปลายทาง** (ย้ายแถวข้ามห้องได้) |
| `POST /api/timetable/requirements/bulk` | **นำเข้าเป็นชุด** — แถวที่ไม่ผ่านถูกปฏิเสธรายแถว ไม่ล้มทั้งไฟล์ ตามแบบเดิมของตัวนำเข้า |

ปล่อยช่องใดช่องหนึ่งไว้แปลว่าการบังคับรั่ว และตัวนำเข้าคือช่องที่ข้อมูลเพี้ยน
เข้ามามากที่สุดตั้งแต่แรก

### จุดที่ **ไม่** บังคับ

- ตัวจัดตาราง ย้ายคาบ ลากวาง — ทำงานกับแถวที่ผ่านด่านมาแล้ว บังคับซ้ำได้แต่ไม่ได้
  อะไรเพิ่ม และทำให้ตารางที่จัดไว้แล้วพังเมื่อหลักสูตรถูกแก้ทีหลัง
- การปรับห้องให้ตรงหลักสูตร (5.4) — มันคือทางที่หลักสูตรเขียนลงไปเอง
- ห้องที่ไม่ได้ผูกหลักสูตร
- **การเปลี่ยนหลักสูตรของห้องที่มีวิชาอยู่แล้ว** — ไม่ไล่ลบย้อนหลัง แถวเดิมยังอยู่
  ครบ และไปโผล่เป็น "เกิน" ในหน้าเทียบกับหน้าตรวจ ให้โรงเรียนตัดสินใจเอง การลบ
  ย้อนหลังอัตโนมัติคือการทิ้งงานของคนอื่นเงียบๆ ซึ่งแอปนี้ไม่ทำที่ไหนเลย

## 7. API

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/curricula` | ทุกหลักสูตร + จำนวนห้องที่ผูกอยู่ |
| POST | `/api/curricula` | สร้างใหม่ (ว่างเปล่า) |
| PUT | `/api/curricula/{id}` | แก้ชื่อ/โน้ต/แถว |
| DELETE | `/api/curricula/{id}` | ลบ (ปฏิเสธถ้ายังมีห้องผูก) |
| POST | `/api/curricula/{id}/copy` | ก๊อปปี้ |
| POST | `/api/curricula/from-group/{gid}` | สร้างจากห้องที่มีอยู่ |
| PUT | `/api/curricula/{id}/groups` | ผูก/ปลดห้อง (`{"group_ids": [...]}`) |
| GET | `/api/curricula/diff/{gid}` | ตารางเทียบของห้องนั้น |
| POST | `/api/curricula/apply/{gid}` | ลงมือตามที่ติ๊ก — สามลิสต์ของ `subject_id`: `{"add": [], "fix": [], "remove": []}` |
| GET | `/api/curricula/audit` | ทั้งโรงเรียน |

## 8. หน้าจอ

1. **⚙ จัดการ → หลักสูตร** — รายการหลักสูตร · กรอกแถว · ก๊อปปี้ · ผูกห้อง ·
   ปุ่ม "สร้างจากห้องที่มีอยู่"
2. **หน้าเทียบ** (โมดัล) — ตาราง ➕✏️➖ ติ๊กแล้วกดรับ
3. **เครื่องมือ → 📚 ตรวจหลักสูตร** — ทั้งโรงเรียน ห้องละบรรทัด
4. **ข้อความตอนถูกปฏิเสธ** — ในหน้าที่เพิ่มวิชา พร้อมลิงก์ไปแก้หลักสูตร

## 9. การทดสอบ

ไฟล์ใหม่ `curriculum.py` (เทสต์) ในชุดเดิม:

- สร้าง/แก้/ลบ · ลบทั้งที่ยังมีห้องผูก → ปฏิเสธ
- ก๊อปปี้แล้วแก้ชุดใหม่ ไม่กระทบชุดเดิม
- ผูกห้อง → ไม่มีวิชาไหนเปลี่ยน
- `diff` ถูกทั้งสามทาง: ขาด · เกิน · คาบไม่ตรง
- `apply` ทำเฉพาะที่ติ๊ก · แถวใหม่เว้นครูไว้ · ไม่แตะคาบในตาราง
- แถวในเซ็ตห้องย่อย/สอนร่วม ไม่ถูกเสนอให้ลบ
- วิชาที่อยู่ในคาบเสรีแล้ว ไม่นับว่าเกิน
- บังคับครบทั้งสามทาง (เพิ่ม · แก้ · นำเข้าเป็นชุด)
- ห้องที่ไม่ผูกหลักสูตร ไม่ถูกบังคับ
- ห้องย่อยผูกหลักสูตรของตัวเองได้ ไม่สืบทอดจากห้องแม่
- บันทึก/กู้คืนแล้วหลักสูตรยังอยู่ครบ (ทั้งสี่จุด)
- ข้อมูลจริงทั้งโรงเรียน: สร้างหลักสูตรจาก ม.4/1 → ผูกทุกห้อง ม.4 → `audit` ชี้ที่
  เพี้ยนได้ และจำนวนแถวรวมไม่เปลี่ยนจนกว่าจะกด `apply`

## 10. ลำดับการทำ

1. `curriculum.py` + ที่เก็บ + CRUD + ก๊อปปี้ + ผูกห้อง + หน้าจัดการ
2. `diff` / `apply` + หน้าเทียบ + สร้างจากห้องที่มีอยู่
3. `audit` + หน้าตรวจทั้งโรงเรียน
4. **เปิดบังคับเป็นอันสุดท้าย**

ลำดับนี้ไม่ใช่เรื่องความสะดวก — เปิดบังคับก่อนที่โรงเรียนจะกรอกหลักสูตรเสร็จ
เท่ากับล็อกตัวเองออกจากข้อมูลของตัวเองตั้งแต่วันแรก

## 11. ความเสี่ยง

| ความเสี่ยง | รับมือ |
|---|---|
| เปิดบังคับแล้วแก้ข้อมูลไม่ได้ทั้งระบบ | ห้องที่ไม่ผูกหลักสูตร = ไม่ถูกบังคับ + บังคับเป็นเฟสสุดท้าย |
| ลบวิชาที่ "เกิน" ทิ้งไปทั้งที่ยังมีคาบในตาราง | `apply` ไม่แตะตาราง + เตือนก่อน |
| เซ็ตห้องย่อยพังเพราะถูกลบข้างเดียว | แถวที่มี `parallel_group_key` ไม่ถูกเสนอให้ลบ |
| หลักสูตรหายตอนรีสตาร์ต | ต่อสายครบสี่จุด + มีเทสต์คุม |
| หลักสูตรกลายเป็นคำตอบที่สองของเรื่องที่ตัววิชาตอบอยู่แล้ว | แถวมีแค่ วิชา + คาบ |
