## 1. เจตนา

ระหว่างภาคเรียน อัตรากำลังเปลี่ยนได้ (ครูย้าย ลาออก แบ่งห้องใหม่ เพิ่ม/ลดคาบ) วันนี้ฝ่ายวิชาการต้องแก้แผนการสอนในโปรแกรมจัดตารางด้วยมือทีละแถว
และจำเองว่าคาบที่ลงไว้แล้วตรงไหนต้องตามแก้ ทาง ข. ทำให้: แก้ในเว็บลงอัตรากำลัง (ที่เดียวกับที่หัวหน้ากลุ่มกรอก) → ในโปรแกรมจัดตารางกด
**"อัปเดตแผนจากรอบอัตรากำลัง"** → เห็นสิ่งที่ต่างแยกเป็นกอง → ติ๊กยอมรับทีละข้อ → แผนเปลี่ยนตามที่ติ๊ก **คาบที่ลงไว้แล้วไม่ถูกแตะ**
และได้ **รายการงานที่ต้องไปแก้เอง** ในโปรแกรม (ขาดกี่คาบ · คาบที่ยังเป็นครูเดิม · คาบเกินแผน) ที่หายไปเองเมื่อแก้แล้ว

## 2. เป้าหมาย / ไม่ทำ / ห้ามเกิด

**เป้าหมาย**
1. ใช้ได้กับรอบของ **ภาคเรียนที่เปิดอยู่** ทั้งรอบที่เคยส่งเข้าเทอมด้วยทาง ก. (เปิดให้แก้กลางเทอมได้ — ข้อ 4.1) และรอบที่ไม่เคยส่ง (เช่นภาคนี้ที่จัดตารางด้วยมือ)
2. หน้าเทียบก่อนเขียน แยกกองตามสเปกหลัก + กองทะเบียน + กองคาบเสรี · ทุกข้อมีช่องติ๊ก **ค่าเริ่มต้นไม่ติ๊ก** (ไม่ติ๊ก = คงเดิม) · มี "เลือกทั้งกอง"
3. แต่ละข้อบอกผลต่อคาบที่ลงไว้แล้ว (เช่น "ลงไว้แล้ว 3 คาบ — จะเข้ารายการงาน")
4. ยืนยันด้วยรหัสผู้ดูแลระบบของเว็บลงอัตรากำลัง · **ทั้งหมดหรือไม่มีเลย** · ประวัติว่าใครกดเมื่อไหร่ ยอมรับ/ไม่ยอมรับข้อไหน
5. รายการงานที่ต้องไปแก้เองอยู่ในโปรแกรมจัดตาราง สถานะคิดจากของจริง (แผนเทียบคาบ) จึงหายเองเมื่อแก้ครบ และกด "ทำแล้ว" เองได้

**ไม่ทำ**
- เขียน/ย้าย/ลบคาบใด ๆ (รวมคาบเสรีที่ลงแล้ว) · ป้าย "เกินแผน" บนตารางคาบ (อยู่ในรายการงานแทน — ไม่แตะหน้าจัดคาบ)
- ลบครู/วิชาในโปรแกรม · ช่องที่โปรแกรมเป็นเจ้าของ (เงื่อนไขของครู ห้องประจำ ฯลฯ)
- เปลี่ยนเทอม (ทาง ก. ทำอยู่แล้ว)

**ห้ามเกิด**
- `SLOTS` หรือ `PARKED` ต่างไปแม้แต่ไบต์เดียวหลังกดยืนยัน ไม่ว่าจะติ๊กข้อใด
- สิ่งที่ไม่ได้ติ๊กเปลี่ยน · แผนเปลี่ยนครึ่ง ๆ กลาง ๆ · ครู/วิชาซ้ำ
- แถวแผนที่รอบไม่รู้จัก (เช่นแถวที่ขั้นที่ 2 แปลงไม่ได้) ถูกเสนอให้ลบ
- ข้อมูลที่หน้าเทียบแสดงต่างจากสิ่งที่ถูกเขียนจริง (ถ้าของเปลี่ยนระหว่างดูกับกด → 409 ให้ดูใหม่)

## 3. ข้อผูกมัด

- ข้อห้ามของผู้ใช้ใน `docs/HANDOFF.md` ทั้งหมด โดยเฉพาะ **"ห้ามมีโค้ดใหม่ที่เขียน `SLOTS`"** และ "ไม่กระทบงานตารางสอน"
- การเขียนของโปรแกรมทำใน route ใต้ `/api/terms/` เท่านั้น (ผ่านตัวนับรุ่น + สำเนาสด) และ route ต้องปฏิเสธเองเมื่อเทอมที่เปิดอยู่ไม่ใช่ `active`
- ไม่เรียก route/ตัวช่วยเดิมที่เขียนคาบเป็นผลข้างเคียง (`_sync_pool_slots` · `/api/timetable/coteach` · `_purge_*` · repair)
- ข้อผูกมัดเดิมของขั้นที่ 1–3: ไทยทั้งหมด · ไม่เพิ่ม dependency · อ้างด้วยรหัส · ไม่มี unique index ใหม่บนตารางที่มีข้อมูล · ทดสอบกับฐานทดลองเท่านั้น ·
  `frontend/` แก้ได้เฉพาะ `components/terms/` `utils/terms.ts` `api/client.ts` `store/timetableStore.ts` (+ ไฟล์ใหม่ใต้ `components/terms/`)

## 4. สิ่งที่ตัดสินแล้ว

### 4.1 รอบไหนใช้ได้ และการเปิดรอบให้แก้กลางเทอม (ผู้ออกแบบตัดสิน)

- รอบต้องเป็นของ **ปี/ภาคเรียนเดียวกับเทอมที่เปิดอยู่** · ทุกรายการครบ (มีครูและยืนยัน) · ทุกกลุ่มตรวจผ่านหรือรอบปิดแล้ว — เกณฑ์เดียวกับทาง ก. ยกเว้นข้อ "ยังไม่เคยส่ง" และ "ยังไม่มีเทอมนี้"
- **รอบที่ส่งด้วยทาง ก. แล้ว** (ล็อกถาวร): เพิ่มปุ่ม admin ในเว็บ **"เปิดให้แก้กลางเทอม"** ใช้ได้เมื่อเทอมของรอบเปิดอยู่ →
  รอบกลับเป็น `filling` (แถวยังยืนยันอยู่ตามเดิม) · ทุกกลุ่มกลับเป็น "กำลังกรอก" · หลักสูตรของภาคนั้นแก้ได้อีก · บันทึก `amending_since` ·
  เครื่องหมาย "ส่งแล้ว" ยังอยู่ (ส่งซ้ำด้วยทาง ก. ไม่ได้) · หลังอัปเดตกลางเทอมสำเร็จ หรือ admin ปิดรอบ → กลับเป็นปิดและอ่านอย่างเดียว
  (เหตุ: หนึ่งภาคเรียนมีได้หนึ่งรอบ และรอบที่ส่งแล้วล็อก — ถ้าไม่มีทางนี้ ภาคเรียนที่สร้างด้วยทาง ก. จะใช้ทาง ข. ไม่ได้เลย)
- **รอบที่ไม่เคยส่ง** ใช้ได้ตรง ๆ · หลังอัปเดตไม่เปลี่ยนสถานะรอบ (กดซ้ำภายหลังเห็นเฉพาะสิ่งที่ยังต่าง)

### 4.2 เทียบอะไรกับอะไร

"แผนที่รอบต้องการ" = ผลของ `registry_plan` + `plan_from_round` (ทาง ก.) โดยใช้ของสดของเทอมที่เปิดเป็น "แผนเดิม" ·
เทียบกับ `REQUIREMENTS` สดเป็นก้อนตาม (ห้อง, วิชา) หลังพับคู่สอนร่วม (`_fold_coteaching`) — **ไม่เขียนผลของ `plan_from_round` ทั้งก้อน** เขียนเฉพาะข้อที่ติ๊ก

| กอง | หมายถึง | กดยอมรับแล้วเกิดอะไร | ผลต่อคาบที่ลงแล้ว (เข้ารายการงาน) |
|---|---|---|---|
| **ข้อมูลครู/วิชา** | ครู/วิชาที่ต้องสร้าง · ช่องตัวตนที่ต่าง (กฎทาง ก. ข้อ 4.3) | สร้าง/แก้ช่องตัวตน · เขียน `sched_id` กลับ | ไม่มี |
| **แถวใหม่** | (ห้อง, วิชา) ที่รอบมีแต่แผนไม่มี | เพิ่มแถวแผน (เพิ่มวิชาเข้าหลักสูตรของห้องถ้าจำเป็น) | "ยังไม่ลง N คาบ" |
| **คาบเปลี่ยน** | คาบ/สัปดาห์ต่าง | แก้ `weekly_count` | "ขาด/เกิน N คาบ" |
| **เปลี่ยนครู** | ครูผู้สอน · ครูสอนร่วม · ห้องปฏิบัติการ ต่าง | แก้ช่องนั้นในแผน | "N คาบที่ลงไว้ยังเป็นครูเดิม/ห้องเดิม" |
| **แถวที่หายไป** | (ห้อง, วิชา) ที่แผนมีแต่รอบไม่มี **และรอบรู้จักแถวนั้น** | ลบแถวแผน | "เกินแผน N คาบ" (คาบยังอยู่ คนตัดสินใจลบเอง) |
| **คาบเสรี** | ตัวเลือกใหม่ · เปลี่ยนครูของตัวเลือก · ตัวเลือกที่ถูกเอาออก (จับชุดกับ pool ด้วยชื่อ + ห้อง) | pool ที่ **ยังไม่ลงคาบ** → แก้รายการตัวเลือก · pool ที่ลงคาบแล้ว หรือช่องคาบเสรีรายห้อง → **ไม่แก้อัตโนมัติ** เข้ารายการงานเท่านั้น | "แก้ตัวเลือกในหน้าคาบเสรีเอง" |

- "รอบรู้จักแถวนั้น" = ห้องอยู่ในหลักสูตรของภาค และ (ห้อง, วิชา) ไม่อยู่ในรายการ `unconverted` ของรอบ และไม่ใช่แถวที่ถูกคาบเสรี/กิจกรรมสอนแทน
  ที่รอบไม่รู้จัก → แสดงเป็นรายการ "ไม่อยู่ในรอบ — ไม่ทำอะไร"
- แถวใหม่/เปลี่ยนครูที่อ้างครู/วิชาที่ยังไม่มีในโปรแกรม → การติ๊กข้อนั้นติ๊กข้อสร้างครู/วิชาที่จำเป็นให้อัตโนมัติ (แสดงให้เห็น)
- เหตุผลที่คาบเสรีที่ลงแล้วไม่แก้อัตโนมัติ: ทางเดียวที่โปรแกรมแก้ตัวเลือกของคาบเสรีที่ลงแล้วคือเขียนคาบ (`_sync_pool_slots` ลบแล้วสร้างคาบใหม่) ซึ่งขัดข้อห้ามของผู้ใช้

### 4.3 ธุรกรรม (แบบเดียวกับทาง ก. ข้อ 4.4 ยกเว้นไม่หมุนเทอม)

`POST /api/terms/plan-update {round_id, admin_code, accept: [รหัสข้อ], preview_token}`:
ตรวจรหัส admin (นับครั้งผิดร่วมกับล็อกอิน) → การเชื่อมต่อเดียว ล็อกทะเบียน → แถวรอบ `FOR UPDATE` → คำนวณหน้าเทียบใหม่ในธุรกรรม →
ถ้าไม่ตรงกับ `preview_token` (ลายนิ้วมือของหน้าเทียบที่ admin เห็น) → 409 "ข้อมูลเปลี่ยนตั้งแต่เปิดหน้าเทียบ — ดูใหม่อีกครั้ง" →
เก็บสำเนาเพื่อย้อนของตัวแปรที่แตะ (**ไม่รวม `SLOTS`/`PARKED` เพราะไม่ถูกแตะ**) → ใส่เฉพาะข้อที่ติ๊ก → สำเนาสด `app_state` ในธุรกรรม → เขียนกลับ `sched_id` ·
บันทึกประวัติ · ปิดรอบที่เปิดให้แก้กลางเทอม → COMMIT ครั้งเดียว · เทียบ `REVISION` ก่อนใส่และก่อน COMMIT (มีคนแก้โปรแกรมระหว่างนั้น → 409) ·
ล้มก่อน COMMIT → ย้อนทั้งหมด

### 4.4 รายการงานที่ต้องไปแก้เอง (ในโปรแกรมจัดตาราง)

- เก็บใน snapshot (คีย์ใหม่ ติดไปกับไฟล์เทอมและสำรอง) เป็นรายการข้อ `{id, update_id, kind, group_id, subject_id, text}` ของข้อที่ยอมรับแล้วกระทบคาบ
- สถานะคิดสดจากแผนเทียบคาบตอนอ่าน: ขาด/เกิน (นับคาบที่ลงของ (ห้อง, วิชา)) · คาบที่ครู ≠ ครูในแผน · คาบเกินแผนของแถวที่ถูกลบ ·
  ข้อคาบเสรีไม่มีเงื่อนไขอัตโนมัติ → ต้องกด "ทำแล้ว" · ข้อที่เงื่อนไขหายแล้วขึ้น "เรียบร้อย" และซ่อนได้
- แสดงในแผงเทอมของโปรแกรม (ที่เดียวกับปุ่มสร้างเทอมใหม่) พร้อมตัวเลขค้าง · ไม่แตะหน้าจัดคาบ

### 4.5 หน้าจอ

- **โปรแกรมจัดตาราง** ปุ่ม "อัปเดตแผนจากรอบอัตรากำลัง" ในแผงเทอม (เห็นเมื่อมีรอบของภาคที่เปิดอยู่) → หน้าต่างเลือกรอบ → กองต่าง ๆ พร้อมช่องติ๊ก จำนวน และผลต่อคาบ ·
  เหตุที่ใช้ไม่ได้ · ช่องรหัส · "ยืนยัน N ข้อ" · ผลหลังกด + ลิงก์ไปรายการงาน
- **เว็บลงอัตรากำลัง** ปุ่ม "เปิดให้แก้กลางเทอม" บนรอบที่ส่งแล้วซึ่งเทอมของมันเปิดอยู่ (ยืนยันก่อน) · ป้าย "แก้กลางเทอม — ยังไม่ส่ง" ·
  ประวัติการอัปเดตกลางเทอม (เมื่อไหร่ · ใคร · ยอมรับ/ไม่ยอมรับกี่ข้อ)

### 4.6 ฐานข้อมูล

`wl_rounds` เพิ่ม `amending_since timestamptz` · ตารางใหม่ `wl_plan_updates (id, round_id, term_id, at, by, accepted jsonb, rejected jsonb, report jsonb)` ·
ทั้งหมด `IF NOT EXISTS` · ไม่มี unique index บนตารางเดิม

## 5. ทางที่พิจารณา

| ทาง | ได้ | เสีย | ผล |
|---|---|---|---|
| **ข1. หน้าเทียบในโปรแกรมจัดตาราง + ติ๊กทีละข้อ + ธุรกรรมเดียว** (ตามสเปกหลัก) | ตรงสเปก · ใช้ชิ้นส่วนทาง ก. · คนเห็นผลต่อคาบก่อนกด | ต้องมีทางเปิดรอบที่ส่งแล้วให้แก้ได้ | **เลือก** |
| ข2. ให้หน้าเทียบอยู่ในเว็บลงอัตรากำลัง | หัวหน้า/admin อยู่ที่เดียว | เว็บลงอัตรากำลังเขียนข้อมูลของโปรแกรมไม่ได้ (ข้อผูกมัดของขั้นที่ 1) ต้องยิงข้ามระบบ | ตก |
| ข3. แทนแผนทั้งชุดแบบทาง ก. กลางเทอม | ง่าย | ขัดสเปก ("เลือกทีละข้อ") · แถวที่รอบไม่รู้จักหาย | ตก |
| ข4. แก้คาบเสรีที่ลงแล้วให้อัตโนมัติ | สะดวก | ต้องเขียนคาบ ขัดข้อห้ามของผู้ใช้ | ตก (เข้ารายการงานแทน) |

## 6. ทดสอบก่อนปล่อย

1. **กฎเหล็ก**: ติ๊กทุกข้อทุกกอง → `SLOTS` และ `PARKED` เท่าเดิมทุกไบต์ (สเปกหลักข้อทดสอบ 3)
2. รอบที่เพิ่งเปิดจากแผนปัจจุบัน (ยังไม่แก้อะไร) → หน้าเทียบ **ว่างทุกกอง** ทั้งข้อมูลตั้งต้นและข้อมูลแบบจริง (ชุด ข ของทาง ก.)
3. แก้รอบให้มีครบทุกกอง → ตรวจเจอครบ · กดไม่ติ๊กเลย → ไม่เขียนอะไรเลยจริง (สเปกหลักข้อทดสอบ 4) · ติ๊กบางข้อ → เปลี่ยนเฉพาะข้อนั้น
4. แถวที่รอบไม่รู้จักไม่ถูกเสนอให้ลบ
5. รายการงาน: คาบ 3→4 ที่ลงแล้ว 3 → "ขาด 1 คาบ" · ลงเพิ่มแล้วหายเอง · เปลี่ยนครูที่ลงแล้ว → "ยังเป็นครูเดิม N คาบ" · ลบแถวที่ลงแล้ว → "เกินแผน N คาบ" · ทั้งหมดรอดการเริ่มเซิร์ฟเวอร์ใหม่
6. คาบเสรี: pool ที่ยังไม่ลงคาบ → ตัวเลือกเปลี่ยน · ลงแล้ว → pool และคาบเท่าเดิม มีข้อในรายการงาน
7. ธุรกรรม: ฉีดล้มทุกขั้น · ฆ่าเซิร์ฟเวอร์หลัง COMMIT · กดพร้อมกัน · แก้โปรแกรมระหว่างกด · หน้าเทียบเก่า (`preview_token` ไม่ตรง) → 409
8. เปิดรอบที่ส่งแล้วให้แก้กลางเทอม → หัวหน้าแก้ได้ → ส่ง/ตรวจผ่าน → อัปเดต → รอบกลับเป็นปิด · ทาง ก. ส่งรอบนั้นซ้ำไม่ได้
9. ทาง ก. (สร้างเทอม · ปลดล็อก) ไม่เปลี่ยน
10. ลองอัปเกรดจากรุ่นบน `main`

## 7. ปล่อยใช้

merge ผ่าน PR นอกเวลาเรียน · คู่มือเพิ่มหัวข้อ "แก้อัตรากำลังกลางเทอม" + ข้อทดสอบด้วยมือ (ลองกับสำเนาฐานจริงก่อนใช้กับเทอมจริงครั้งแรก)

## 9. ข้อเท็จจริงของโค้ด (ณ `20da99c` — ใช้ grep ยืนยัน)

- คาบไม่มี `requirement_id` — ผูกกับแผนด้วย (ห้อง, วิชา) และครูสำหรับคู่สอนร่วม · คาบที่ขาดต่อแถวแผนมีอยู่แล้ว (`_unplaced_report` ~1719 · `GET /api/timetable/unplaced`) แต่ไม่ดูครู ·
  `GET /api/diagnostics/consistency` (~7217) มี `over_placed` · ไม่มีที่ไหนตรวจ "คาบที่ครูไม่ตรงแผน" · "เกินแผน" มีแค่ประโยคใน `AnalyticsPanel` ไม่มีป้ายบนคาบ
- route แก้แผนเดิม (`PUT`/`DELETE`/bulk requirements ~10176–10296) ไม่แตะคาบ · ตัวช่วยที่เขียนคาบเป็นผลข้างเคียง: `POST /api/timetable/coteach` · repair · `_purge_*` · `_sync_pool_slots` (~11197 ลบแล้วสร้างคาบของ pool ใหม่ทั้งหมด)
- pool ที่ยังไม่ลงคาบ (`day`/`period` ว่าง): แก้ตัวเลือกได้โดยไม่มีคาบให้เขียน
- รอบที่ส่งแล้ว: `_wl_refuse_exported` (~15445) ถูกเรียกจาก `_wl_refuse_locked` · `_wl_round_for_update` · `_wl_round_for_write` · `_wl_option_for_write` · `wl_round_export_state` (~15401) ·
  CHECK ของสถานะรอบรับ `closed → filling` ได้ · index "รอบที่ยังไม่ปิดมีได้หนึ่งรอบ" ยังบังคับ
- ชิ้นส่วนของทาง ก. ที่ใช้ซ้ำ: `registry_plan` · `plan_from_round` (ไม่อ่าน `outgoing["slots"]`) · `_wl_export_source` · `_term_build` · `_term_admin_check` · `_wl_registry_lock` · คู่เทียบ `REVISION` · `_DB_UPSERT`
- `/api/terms/*` อยู่ใน `TERM_WRITE_SAFE_PATHS` → route ใหม่ต้องเช็กเองว่าเทอมเปิดอยู่ · snapshot (`_snapshot` ~13418) เป็นที่เก็บที่ติดไปกับไฟล์เทอม
