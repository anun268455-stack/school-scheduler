## ข้อห้ามที่ยังมีผลตลอด (ผู้ใช้สั่งเอง)

1. **"ตอนนี้คาบโอเคแล้วห้ามยุ่ง"** · **"ที่สำคัญคือจะไม่กระทบกับงานตารางสอนเพราะตอนนี้ตารางสอนยังไม่นิ่ง"**
   ห้ามมีโค้ดใหม่ที่เขียน `SLOTS` (และ `PARKED` ถาดพักคาบ) เครื่องจัดตารางเสนอได้ ไม่เขียนคาบเอง · เว็บลงอัตรากำลังอ่านข้อมูลของโปรแกรมจัดตารางอย่างเดียว
   (ทาง ข. เขียนแผน/ครู/วิชา/คาบเสรีที่ยังไม่ลงคาบของโปรแกรมได้เฉพาะผ่าน route ใต้ `/api/terms/` และไม่แตะคาบเลย)
2. **สายเชื่อมต่อฐานข้อมูลคือรหัสผ่าน** ห้ามส่งในแชต ห้าม commit ผู้ใช้กรอก `DATABASE_URL`
   เองใน Environment ของ Render โค้ดอ่านจาก `os.environ`
   **`WORKLOAD_SETUP_CODE` (รหัสตั้งค่าของเว็บลงอัตรากำลัง) เป็นความลับชนิดเดียวกัน** ใช้กติกาเดียวกันทุกข้อ ·
   รหัสผู้ดูแลระบบ/รหัสกลุ่มสาระก็ห้ามอยู่ในแชต ใน commit หรือในภาพหน้าจอ (คนพิมพ์เองที่หน้าเว็บเท่านั้น · เอกสารใช้ `<รหัสผู้ดูแล>`)
3. **ห้ามส่งไฟล์สำรองจากเครื่องชั่วคราวให้ผู้ใช้กู้คืน** สำเนาในเครื่องนี้เก่ากว่าของจริงเสมอ
4. เข้าฐานข้อมูลจริงของผู้ใช้ไม่ได้ อ่านก็ไม่ได้ เขียนก็ไม่ได้
5. ตอบเป็นภาษาไทยทุกครั้ง
6. (ขั้นที่ 2) **"ยังไม่ยืนยัน" หายได้เพราะคนกดยืนยันหรือเลือกครูเองเท่านั้น** · **หัวหน้ากลุ่มสาระเห็นและแก้ได้แค่กลุ่มตัวเอง บังคับที่เซิร์ฟเวอร์**

4. ปลดล็อกเทอม (กดผิด): ทะเบียนครู/วิชาของเว็บถูกปรับให้ชี้ตามข้อมูลของเทอมที่เปิดอยู่เองทุกครั้ง (ไม่ว่าจะปลดล็อกลำดับใด) · รอบที่ส่งแล้วแก้ไม่ได้ถาวร

- รอบใช้ได้ = ทุกรายการมีครูและยืนยัน + (ทุกกลุ่มตรวจผ่าน **หรือ** admin ปิดรอบแล้ว) + ปี/ภาคยังไม่มีเทอม
- แถวแผนของวิชาเสรีและแถวในคาบกิจกรรมทั้งระดับเขียนตามรูปของแผนเดิม (ยอดคาบรายครูเท่าเดิม) · เซ็ตห้องย่อย/คาบที่ปักยกจากแผนเดิมเมื่อห้อง+วิชาตรง
- ผูกวิชาด้วยรหัสวิชาเมื่อโปรแกรมมีรหัสนั้นวิชาเดียว (แทนการสร้างซ้ำ) · ครูที่เว็บติ๊กไม่ปฏิบัติงานแล้วไม่ถูกปิดในโปรแกรม
- ถ้ามีคนแก้ข้อมูลในโปรแกรมระหว่างกด → 409 ให้กดใหม่ (คู่มือบอกให้ไม่แก้ระหว่างกด)
- แก้บั๊กของขั้นที่ 2 ที่ขึ้นเว็บแล้ว: `wl_prefill` สลับคาบของคู่สอนร่วมคาบไม่เท่ากันตอนเปิดรอบ —
  **รอบที่เปิดบนเว็บจริงก่อนวันนี้ (ถ้ามี) ให้ admin ตรวจแถวที่มีธงเตือนครูสอนร่วมคาบไม่เท่ากันด้วยตาเอง** การแก้ไม่ย้อนไปแก้รอบที่เปิดแล้ว

### 5. ทาง ข. อัปเดตแผนกลางเทอมจากรอบอัตรากำลัง — เสร็จบนสาขา รอ merge

- แบบที่ผู้ใช้อนุมัติ: `docs/superpowers/specs/2026-11-18-workload-midterm-update-design.md` (ทำตามสเปกหลักส่วนที่ 7)
- แผน: `docs/superpowers/plans/2026-11-18-workload-midterm-update.md` (5 task) · สมุดการตัดสินใจ: `docs/decisions/2026-11-18-workload-midterm-decisions.md`
- คู่มือ: `docs/workload-setup.md` **ข้อ 11ก "แก้อัตรากำลังกลางเทอม"** + ข้อทดสอบด้วยมือในข้อ 15
- ตัวทดสอบ: `bash tests/run.sh` → ผ่าน 36 · ไม่ผ่าน 0 · lint/build สองเว็บสะอาด (เว็บตารางมีคำเตือนเดิม 26 ตัว)

admin ใช้อย่างไร (ย่อจากคู่มือข้อ 11ก)
1. รอบที่ **ปิดแล้ว** ของภาคเรียนที่เปิดอยู่ในโปรแกรม **ใช้ได้เลย** — โปรแกรมจัดตาราง → ⚙ จัดการ → 🗓 เทอม → **อัปเดตแผนจากรอบอัตรากำลัง**
2. ถ้าจะแก้อัตรากำลังกลางเทอม: เว็บลงอัตรากำลัง → รอบเก่า → เปิดดู → **เปิดให้แก้กลางเทอม** (ทุกกลุ่มกลับเป็น "กำลังกรอก") → แก้ →
   **ปิดรอบ** (หรือให้ทุกกลุ่มที่มีรายการส่งแล้วตรวจผ่าน) → กดอัปเดตในโปรแกรม
3. หน้าต่างแสดงสิ่งที่ต่างจากแผนเป็นหกกอง (ข้อมูลครู/วิชา · แถวใหม่ · คาบเปลี่ยน · เปลี่ยนครู · แถวที่หายไป · คาบเสรี/กิจกรรม) **ค่าเริ่มต้นไม่ติ๊ก**
   แต่ละข้อบอกผลต่อคาบที่ลงไว้ → ติ๊กรับทีละข้อ → รหัสผู้ดูแลระบบของเว็บลงอัตรากำลัง → ธุรกรรมเดียว **ไม่แตะคาบ**
4. สิ่งที่ต้องไปแก้เองในหน้าจัดคาบ (ขาด/เกินแผน · ยังเป็นครูเดิม · คาบเสรีที่ลงแล้ว/กิจกรรม) ขึ้นใน **รายการงานที่ต้องไปแก้เอง** ท้ายหน้า 🗓 เทอม
   — หายเองเมื่อแผนกับคาบตรงกัน · ข้อคาบเสรี/กิจกรรมกด "ทำแล้ว" เอง
5. หน้ารอบในเว็บมี **ประวัติการอัปเดตแผนกลางเทอม** (เมื่อไหร่ · ใคร · ยอมรับ/ไม่ยอมรับกี่ข้อ)

### หมายเหตุการขึ้นเว็บ (ทาง ข.)

1. merge ผ่าน PR **นอกเวลาเรียน** · DDL (`amending_since` และ `wl_plan_updates`) ขึ้นเองตอนคำขอแรกของเว็บลงอัตรากำลัง ไม่ต้องทำอะไร
2. **สภาพตั้งต้นของเว็บจริง (ยังไม่เคยสร้างเทอม · มีรอบ 2/2569 ที่ปิดแล้ว · ตารางมีคาบ) ลองอัปเกรดแล้วผ่าน** (รีวิวทั้งสาขา บนฐานทดลอง):
   - รันเซิร์ฟเวอร์รุ่น `main` สร้างสภาพนั้น แล้วเปิดรุ่นสาขาบนฐานเดียวกัน — DDL ขึ้นเองไม่มี log ผิด
   - รอบขึ้น "ใช้ได้" หน้าเทียบว่างทุกกอง
   - เปิดให้แก้ → แก้ → อัปเดต: md5 ของคาบ/ถาดพักเท่าเดิม
   - ขึ้นเทอมใหม่/ปลดล็อกกลับ: รายการงานถูกต้อง · ดึงครูสร้าง 0 แถว
3. **ใช้จริงครั้งแรก: ซ้อมกับสำเนาฐานข้อมูลจริงก่อน** (คู่มือข้อ 15 รายการ "แก้อัตรากำลังกลางเทอม")
   - กดอัปเดตกับรอบที่ปิดแล้วโดย **ไม่ต้องเปิดให้แก้**
   - หน้าเทียบ "ว่างทุกกอง" คาดได้เฉพาะเมื่อรอบเปิดจากแผนปัจจุบันของโปรแกรมแล้วไม่มีใครแก้ทั้งสองฝั่ง
   - ภาคนี้ตารางจัดด้วยมือ ข้อที่ขึ้นต้องเป็นส่วนที่รู้อยู่แล้วว่าต่างกันจริงเท่านั้น — มีข้อที่อธิบายไม่ได้ ให้หยุดก่อนกดยืนยัน
4. ระหว่างกดอัปเดต ให้คนจัดตารางหยุดแก้ข้อมูลสักครู่ — การแก้ที่ชนพอดีในช่องราว 100 ms ระหว่างใส่กับ COMMIT ถูกย้อนถ้าคำขอนั้นได้ 409 (ราคาเดียวกับทาง ก.)
5. **ก่อนย้อนกลับไปรุ่นเก่าของ `main` (revert/rollback) ให้ปิดทุกรอบที่กำลังเปิดให้แก้กลางเทอมก่อน**
   - เหตุ: รุ่นเก่าไม่รู้จัก `amending_since` — รอบที่ส่งแล้วซึ่งค้างสถานะ "เปิดให้กรอก" จะถูกรุ่นเก่าปฏิเสธการปิด (เห็นว่าส่งแล้ว)
   - ผล: รอบนั้นขวางการเปิดรอบใหม่ทุกรอบ (ดัชนี "รอบที่ยังไม่ปิดมีได้รอบเดียว") จนกว่าจะขึ้นรุ่นนี้กลับ
   - คอลัมน์/ตารางใหม่อยู่ต่อได้ รุ่นเก่าไม่อ่าน

ทุกอย่างลองแล้วกับเซิร์ฟเวอร์จริง (FastAPI + PostgreSQL 16) และเบราว์เซอร์จริง (Chromium) **ในเครื่องพัฒนา** ด้วยข้อมูลตั้งต้นที่มากับโค้ด ยังไม่เคย

2. ข้อทดสอบด้วยมือในคู่มือ `docs/workload-setup.md` (หัวข้อ "ต้องลองด้วยมือก่อนให้คนในโรงเรียนใช้") · ข้อ 7 ของสเปกหลัก (เทียบหน้าสรุปกับไฟล์ Excel เดิม) ผู้ใช้ต้องเทียบเอง
3. เบราว์เซอร์อื่นนอกจาก Chrome/Edge (Firefox, Safari, มือถือจริง) — ช่องเลือกครูแบบใหม่และหน้าต่างสร้างเทอมลองแค่ Chromium
4. **ปุ่ม "สร้างเทอมใหม่" ทั้งแบบแผนเดิมและแบบจากรอบ กับสำเนาฐานข้อมูลจริง** — ซ้อมก่อนกดบนเว็บจริงครั้งแรก (คู่มือข้อ 15) ·
   ถ้าทำได้ ซ้อมฆ่าเซิร์ฟเวอร์ทันทีหลังกดแล้วเปิดใหม่ ดูว่าเทอม แผน และทะเบียนตรงกัน
5. **ปุ่ม "อัปเดตแผนจากรอบอัตรากำลัง" (ทาง ข.) กับสำเนาฐานข้อมูลจริง** — ตามหมายเหตุการขึ้นเว็บข้อ 3 · ยังไม่เคยลองบนเว็บจริง:
   กรณีเทอมปัจจุบันของเซิร์ฟเวอร์เป็น "ปิด" (ไม่มี route ทำได้ — ครอบด้วยตัวทดสอบหน่วย) และชุดคาบเสรีที่ "จับคู่ไม่ได้" (ข้อมูลทดลองไม่มี)

## ทำต่อจากตรงนี้

ให้ admin ใช้กับภาคเรียนนี้ · งานใหม่ต่อจากนี้เริ่มด้วย `superpowers:brainstorming` เหมือนเดิม
(ผู้ใช้เลือกวิธีลงมือแบบมีคนตรวจแยกทุก task — `superpowers:subagent-driven-development`)

ข้อที่รอได้ของทาง ข. (รีวิวทั้งสาขาคัดแล้ว 44 ข้อ — ไม่มีข้อไหนขวางการขึ้นเว็บ · สรุปตามส่วน ข้อที่แก้ไปแล้วไม่อยู่ในรายการ)
- **เว็บลงอัตรากำลัง:**
  - ปุ่ม "เปิดให้แก้กลางเทอม" ยังขึ้นบนรอบที่ปิดแล้วซึ่งไม่เคยส่งของภาคเรียนอื่น (เซิร์ฟเวอร์ตอบ 409 ไทย) เพราะเว็บไม่รู้ว่าโปรแกรมเปิดภาคไหนอยู่
    — ทางแก้: เพิ่มช่อง `running` ใน `wl_round_view`
  - route ประวัติไม่มี LIMIT (แถวละไม่กี่แถวต่อรอบ)
  - **ควรแก้ก่อน:** กล่องยืนยันปิดรอบ (`RoundsPage.tsx` ~280) และข้อความ 400 ของเซิร์ฟเวอร์ (`mock_api.py` ~16946) ยังบอกว่าปิดแล้ว "ถาวร / หลักสูตรล็อก"
    ทั้งที่คู่มือข้อ 11ก ให้ปิดรอบหลังแก้กลางเทอม (รอบของภาคที่เปิดอยู่เปิดให้แก้ได้อีก) — ทำให้ admin ลังเล
  - รอบที่ปิดแล้วแต่มีแถวยังไม่ยืนยัน ใช้อัปเดตทันทีไม่ได้ (ต้องเปิดให้แก้ ยืนยัน แล้วปิด) — คู่มือข้อ "ใช้ได้เลย" ควรบอกกรณีนี้
  - ถ้าแท็บอื่นปิดรอบระหว่างโหลดหลังเปิดให้แก้ กล่องผลค้างปุ่มเทาจนเปลี่ยนหน้า (เกิดยากมาก)
- **เติมครูตอนเปิดรอบ (`wl_prefill`):**
  - ชุดที่ถูกเปลี่ยนชื่อและห้องตรงกันกับอีกชุด → ถอยไปใช้ห้องซ้อน — ทางแก้: จับคู่ชุดที่เหลือชุดเดียวแบบ `plan_diff._match_sets` (~6 บรรทัด)
  - ชุดไม่มีห้องนับว่าห้องตรง · ถอยไปห้องซ้อนทีละชุดไม่ใช่ทีละวิชา (ทั้งหมดแค่ค่าแนะนำที่หัวหน้ายืนยันเอง)
- **เครื่องเทียบ (`plan_diff.py`):**
  - กฎเพิ่มวิชาเข้าหลักสูตรอยู่สองที่ (ตัวทดสอบผูกทั้งคู่)
  - ข้อความ detail ของข้องานเมื่อจับแถวไม่ได้เลือกแถวแรกที่ใกล้สุด · คู่ที่คาบ (6,6) บอก "ครูสอนร่วม" เสมอ (สถานะถูก แค่ถ้อยคำ)
  - คาบถูกไล่สองรอบ · ตัวทดสอบที่ขาด: ข้อมูลห้องคาบเสรีซ้อนกัน · ห้องแม่หลายชั้น · "ไม่มีช่องเปลี่ยน → ไม่มีข้องาน" · ข้อชุดใน ⇔
- **ทาง ก. ที่รู้แล้ว (เกิดยาก):**
  - ชุดของห้องตรงกับชุดของห้องแม่เปิดวิชาเดียวกัน → ครูของแถวตามรูปเดิมอาจสลับ
  - แถวที่สอนผ่านสำเนาคาบ pool เก่าที่ตัวเลือกต่างกันถูกทิ้ง (มีมาก่อน — ทาง ข. แสดงเป็น "ไม่อยู่ในรอบ" แทน)
- **เซิร์ฟเวอร์ทาง ข. (ความสะอาดของโค้ด/ความเร็ว ไม่มีผลกับผู้ใช้):**
  - `_plan_update_restore` ซ้ำกับ `_term_restore` · SELECT `amending_since` ซ้ำสองที่ · อ่านภาคที่เปิดอยู่สองครั้ง
  - ช่อง `accepted[].auto` ของประวัติใช้ชื่อซ้ำความหมายอื่น
  - รายการรอบคำนวณหน้าเทียบของทุกรอบ (~60 ms ต่อครั้ง ยิงสองครั้งหลังอัปเดต)
  - token ผูกกับการอัปเดตของทั้งฐาน (การอัปเดตรอบอื่นทำให้หน้าเทียบที่เปิดค้างต้อง "ดูใหม่")
  - บันทึกประวัติเทอมตอนยังไม่เคยสร้างเทอมมี term_id ว่าง
- **เว็บตาราง:**
  - แผงรายการงานระหว่างเปิดดูเทอมที่ปิด กดได้กับรายการของเทอมปัจจุบัน (ไม่มีป้ายบอก)
  - `planRoundsNote` ซ้ำกับ `roundsLoadNote`

ข้อเล็กของขั้นที่ 3 ที่รอได้ อยู่ในสมุดการตัดสินใจของขั้นที่ 3 (บรรทัดที่มีคำว่า `minor (deferred`) — ที่ควรดูก่อน:
COMMIT ที่ล้มแบบกำกวมถูกนับเป็นการย้อน (เหมือนปุ่มเดิม) · คำขอแรกของเว็บลงอัตรากำลังหลังเซิร์ฟเวอร์ตื่นช้าลงเพราะ DDL ทีละคำสั่ง (22 รอบไปกลับ) ·
ข้อความเหตุของรอบอาจหลอกในช่วงที่ข้อมูลโรงเรียนยังโหลดไม่เสร็จ

ข้อเล็กที่รู้แล้วว่ายังไม่ได้แก้ อยู่ในไฟล์ decisions ของขั้นที่ 2 (บรรทัดที่มีคำว่า `minor (deferred`) — ที่ควรทำก่อน
1. ร่างครูหายเมื่อพับการ์ด/เปลี่ยนตัวกรอง/เปลี่ยนแท็บ (ไม่บันทึกผิด แต่ที่เลือกไว้หาย)
2. ย้ายบรรทัดหลักสูตรไปกลุ่มอื่นระหว่างรอบ แถวยังคงสถานะ "ยืนยันแล้ว" ไปที่กลุ่มใหม่
3. ความคมชัดของขอบช่องกรอกและป้ายสีเทา (ต่ำกว่าเกณฑ์อ่านง่ายเล็กน้อย)
4. ตั้งต้นหลักสูตรใส่ภาคเรียนที่มีรอบเปิดให้กรอกอยู่แล้ว ยังไม่ถูกกันเรื่องกลุ่มสาระว่าง (แทบไม่เกิด)

## เครื่องมือลองกับของจริงในเครื่องพัฒนา (หายไปพร้อมเครื่อง ต้องตั้งใหม่ทุก session)

ของปลอมใน `tests/stubs` จับความผิดของ SQL และของ HTTP จริงไม่ได้ — ขั้นที่ 2 เจอการแข่งกันของการล็อกและบั๊กหน้าจอจากการลองของจริงหลายครั้ง

```bash
python3 -m venv /tmp/wl-venv && /tmp/wl-venv/bin/pip install fastapi==0.115.0 uvicorn==0.30.6 "psycopg[binary]>=3.1"
runuser -u postgres -- /usr/lib/postgresql/16/bin/initdb -D /var/lib/postgresql/wl-test -A trust -U postgres
runuser -u postgres -- /usr/lib/postgresql/16/bin/pg_ctl -D /var/lib/postgresql/wl-test -o "-p 54329" -w start
runuser -u postgres -- psql -p 54329 -h 127.0.0.1 -U postgres -c "CREATE DATABASE wltest ENCODING 'UTF8' TEMPLATE template0"
DATABASE_URL=<สายเชื่อมต่อฐานทดลองในเครื่อง: ผู้ใช้ postgres ไม่มีรหัส · 127.0.0.1 พอร์ต 54329 · ฐาน wltest> PORT=18000 WORKLOAD_SETUP_CODE=<คิดเองยาว 12 ตัวขึ้นไป> /tmp/wl-venv/bin/python mock_api.py
```

ฐานข้อมูลต้องเป็น UTF8 (แบบเดียวกับ Neon) · หน้าเว็บ: `cd workload && npm ci && VITE_API_URL=http://127.0.0.1:18000 npm run build && npx vite preview --port 4174`
แล้วขับด้วย Playwright ที่ติดตั้งมากับเครื่อง · **ถ่ายภาพที่ 1024 และ 1093 ด้วย** (โน้ตบุ๊ก 1366 ที่ซูม 125%) ไม่ใช่แค่ 1280/390 —
ปัญหาชื่อครูถูกตัดของขั้นที่ 2 หลุดมาถึงรีวิวทั้งสาขาเพราะเหตุนี้
การแข่งกันของสองคำขอ: เปิด `psql` อีกหน้าต่างแล้ว `BEGIN; SELECT … FOR UPDATE;` ค้างไว้ระหว่างยิง route
ทาง ข.: `SCHED_TEST_FAIL_AT=<ขั้น>` ฉีดล้มในธุรกรรมของการอัปเดต (`plan_built` … `plan_commit` · `plan_after_commit` = ฆ่า process หลัง COMMIT ·
`wait:<ขั้น>` = หน่วงไว้ให้คำขออื่นแทรก) — production ห้ามตั้ง · เว็บตาราง build ด้วย `VITE_API_URL=http://127.0.0.1:18000` แล้ว `npx vite preview --port 4173`
